# dc-ops (`crates/ops`)

Реестр всех команд эффектов, разбор аргументов командной строки и планов, применение пачкой и dry-run, ошибки с подсказками; `evaluate` проекта.

## Инварианты

- Команда для CLI и планов — тип с трейтом `dc_core::Op`: его поля = аргументы. Один тип обслуживает командную строку, план и `help --json`.
- `Registry::new` проверяет правила каждой команды (имя, одна строка описания, пример начинается с имени, `deny_unknown_fields`, позиционные поля существуют). Нарушение = ошибка при сборке реестра, её ловит тест.
- `apply`: любое число шагов — одна запись истории, всё или ничего. Ошибка называет номер шага. Dry-run меняет копию, проект и история не трогаются. Изменение «впустую» в историю не пишется.
- `apply_commands` — то же для готовых команд (не из реестра), например `clip add` после копирования файла.
- Настройки (`settings.rs`): команда с `Op::SETTINGS` — команда настроек своего эффекта под этим ключом (ключи уникальны, проверяет `Registry::new`); `settings_steps` превращает `ключ.аргумент=значение` в шаг этой команды (значение — как у `--аргумент`), поэтому `devcast set` и `defaults set` проверяет сама команда.
- Аргументы: `--min-gap` → поле `min_gap`; значение — JSON, если поле не строка по схеме.
- Ошибки по-русски, с подсказкой, что запустить (`devcast help <команда>`). `OpsError::Usage` — неверный запрос (CLI: код 2), `OpsError::Failed` — команда не выполнилась на этом проекте (код 1).
- Реестр всех команд и эффектов DevCast — `Registry::devcast()` (`devcast.rs`), один для CLI и редактора; новый эффект добавляет сюда `ops()` и `effect()`.
- `Registry::resolve` находит команду по первым словам строки (самое длинное имя). Поля `project`, `json`, `dry_run` заняты глобальными флагами (`RESERVED_FIELDS`).
- `Evaluator` (`evaluate.rs`, решение 015) — единственный источник `Scene` для превью, экспорта и `frame`/`sheet`: `new(project, cursors, keys, &mut measure)` один раз строит `TimeMap`, читает состояния эффектов и `canvas`, готовит путь курсора (`dc_fx_cursor::Prepared`; телеметрию `CursorTracks` и `KeyTracks` читает вызывающий; нажатия клавиш ставит на выход `dc_fx_keys::Prepared`) (ошибки `EvaluateError`: битое состояние, нет клипов), `evaluate(t)` — чистая функция, вызывает `evaluate` эффектов в постоянном порядке (видео `cut`, камера `zoom` — трек камеры строится в `new`, аннотации — `annotations.rs`: поля видов читаются в `new` (шрифт текста проверяется по `TextMeasure`), в кадре — `shown_at` показанного момента записи, место с ключами и анимацией — `Placement::at`, поля вида между ключами — `dc_fx_annotations::keyed` по типу вида (шрифт проверяется у каждого ключа), вид → слой `Band::Annotations` (текст `dc_fx_text`, фигура `dc_fx_shape` — один `Layer::Shapes`, градиент по времени выхода, картинка `dc_fx_image` — `Layer::Sprite`, кадр анимации по `shown_for`, рисунок `dc_fx_drawing` — `Layer::Drawing`, без штрихов слоя нет, размытие `dc_fx_blur` — `Layer::Blur`), курсор, облачко — точку ему даёт `dc_fx_cursor::pointer`, субтитры — раскладка `dc_fx_captions::Prepared` в `new` по шрифтам `TextMeasure`, решение 016, клавиши). Новый эффект с картинкой добавляет сюда свой вызов. Зависит от `dc-render` и крейтов эффектов; `dc-encode`/`dc-media` напрямую — только в dev-зависимостях эталонов (через dc-audio они в сборке есть); dc-capture — ради автозумов (ниже).
- Уровни звука (`sound.rs`): `levels(root, project)` переводит `dc_fx_audio_tracks::sound` во вход `dc_audio::Mixer` — один для экспорта (dc-cli) и воспроизведения редактора (dc-app); поэтому dc-ops зависит от dc-audio. Звук из файла (`sound_file.rs`): `import_sound(dir, файл, место)` копирует файл в `assets/audio/` и даёт `AudioAdd`, `discard` удаляет копию, если команду отвергли — один путь для `devcast audio add` и редактора (поэтому и dc-project). Картинка из файла (`picture_file.rs`): `import_picture(dir, файл, (id, at))` копирует её в `assets/images/` и даёт `ImageSet`, `discard` — так же; один путь для `devcast image set` и «Заменить…» редактора (поэтому dc-media).
- Автозумы (`autozoom.rs`, 7.14): `click_zooms(папка, проект)` читает телеметрию записей (`dc_capture::project::recorded`) и отдаёт предложения `dc_fx_zoom::suggest`, `click_commands` — их `ZoomAdd` (применять `apply_commands` одной записью истории `zoom add`), `no_click_zooms` — почему зумов нет. Один путь для `devcast zoom suggest`, `zoom add --at clicks`, автозумов после записи и «Подобрать зумы» редактора. Это не команда реестра: команда — чистая функция проекта, а клики лежат в файлах записей.
- Процесс распознавания редактора (`recognition.rs`, решение 018): протокол `devcast --captions-worker` — `WORKER_ARG`, запрос `Request` (папка, проект, `Speech`: модель `dc_models::Model`, язык, дорожки) JSON в stdin, ответ — строки `Message` (`progress <0..1>`, затем `cues <JSON>` или `error <текст>`, всегда одна строка). Здесь, потому что его линкуют и `devcast` (процесс), и `devcast-app` (редактор). Само распознавание (whisper) — в dc-cli (`speech.rs`): dc-ops не зависит от dc-transcribe, иначе окно программы потянет whisper и Vulkan (правило `xtask verify`).
- Ответ на изменение — одна строка `Applied` (Display): слитый `Diff` пачки и `длительность до→после`, если она изменилась; `без изменений`; префикс dry-run.

## Как тестировать

- `cargo nextest run -p dc-ops`. Тестовая команда `note set` в `src/tests.rs`. `src/annotations_shape_tests.rs`: стрелка в боксе без шрифтов, draw-in по времени выхода через вырез, ключи и градиент. `src/annotations_drawing_tests.rs`: пустой рисунок без слоя, штрихи в боксе, draw-in по времени выхода через вырез, прозрачность по ключам. `src/annotations_blur_tests.rs`: область в px с силой и углами v1, поворот, размытие над нижними дорожками, fade и ключи по времени выхода через вырез. `src/annotations_image_tests.rs`: картинка вписана в бокс, кадры GIF по времени выхода через вырез, картинка ключа, fade. `src/annotations_tests.rs`: порядок слоёв, бокс в px, время через вырез, анимации в слое текста, ключи (бокс, поворот, размер и цвет между ключами через вырез, шрифт ключа), нет шрифта и битые поля до кадра. `src/evaluate_tests.rs`: нет клипов, размер и чёрный кадр вне видео, битое состояние, insta-снимки сцены на вырезе и стыке, клипов в кадре 4:3 и камеры зума через вырез (`src/snapshots/`; после намеренной смены — `INSTA_UPDATE=always` и просмотр diff). `tests/golden.rs` — один бинарник эталонов на программном адаптере (`tests/common` — видео-полосы и картинки курсора фикстуры `clicks.dcproj`): `golden/crop.rs` (`crop/*`: формат 16:9, свободный, второй клип с полями), `golden/cursor.rs` (`cursor/*`: настоящая телеметрия фикстуры), `golden/callout.rs` (`callout/*`: облачко у настоящего курсора, печать, градиент со свечением, переход у края), `golden/captions.rs` (`captions/*`: цвета слов, две строки, тень без плашки, середина pop), `golden/keys.rs` (`keys/*`: сочетания фикстуры `typing.dcproj`, шрифты `.deps/fonts`), `golden/zoom.rs` (`zoom/*`: зум удержан, на входе, фокус в углу), `golden/text.rs` (`text/*`: по умолчанию, поворот с плашкой, начертание и выравнивание, поворот под зумом), `golden/motion.rs` (`motion/*`: середина pop, выезда повёрнутого текста, печати с плашкой), `golden/keyframes.rs` (`keyframes/*`: середина между ключами — бокс, размер, цвет плашки; повёрнутый и сдвинутый ключами текст), `golden/shape.rs` (`shape/*`: все фигуры, градиенты со свечением, середина draw-in, повёрнутые под зумом), `golden/drawing.rs` (`drawing/*`: карандаш, прямая, точка и ластик, середина draw-in, повёрнутый полупрозрачный под зумом), `golden/image.rs` (`image/*`: вписывание в широкий и высокий бокс и кадр GIF, повёрнутые под зумом с pop; картинки `fixtures/images`, `common::check_pictures`), `golden/blur.rs` (`blur/*`: чистое, тонированное и сплошное над линией нижнего слоя, повёрнутые под зумом с pop).

## Куда не лезть

- Сами команды — в крейтах `fx/*`. Undo и проверка целостности — `dc-core::History`. Файлы проекта — `dc-project`.
