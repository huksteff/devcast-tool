# dc-project (`crates/project`)

Папка проекта `.devcast` на диске: project.json, session.json, history.jsonl, lock, версии схемы, настройки по умолчанию приложения.

## Инварианты

- Запись файлов только атомарная (`atomic::write`: tmp → fsync → rename), в процессе — по одной (два rename в один файл сразу Windows отказывает). `history.jsonl` — дозапись; оборванная последняя строка пропускается.
- `project.json` — сохранённое (Ctrl+S), `session.json` — рабочее (автосохранение). Есть `session.json` = есть несохранённое; после вылета проект открывается из него.
- Имя проекта — `ProjectDir::name` (имя папки, верное и для пути `..`); из `root()` его не выводить.
- Писатель один: `ProjectLock` держит OS-блокировку файла `lock`; после падения процесса ОС снимает её сама. `lock-owner.json` только подсказывает, кто держит.
- Загрузка: JSON → миграции (`migrate.rs`) → `Project` → `problems()`. Новее схемы — отказ с «обнови программу». Новая версия схемы = новая функция в `MIGRATIONS`.
- История: журнал событий do/undo/redo, первая строка — версия схемы снимков. Пишется перед session/project. Журнал другой версии (или без неё) не мигрируется (снимки частичные, миграции — над целым project.json): история начинается заново с предупреждением. При загрузке стеки сверяются с проектом; не сходятся — история начинается заново, проект открывается всё равно.
- Настройки по умолчанию копируют только поле `settings` состояний эффектов, содержимое не трогают. `apply` добавляет их в новый проект, `restyle` (`style copy`) заменяет: эффект без настроек в источнике возвращается к заводским, опустевшее состояние удаляется.
- Кэш (`cache.rs`): производные данные файла проекта лежат в `cache/` по его пути с суффиксом (`ProjectDir::cache_file`), годны, пока у файла тот же `FileStamp` (размер и время изменения). Им пользуются probe, превью, волна, распознанные слова.
- Файл в папку проекта (`copy_in`: картинки, доп. звук) — под своим именем, занято другим файлом — `-2`, `-3` …, тот же файл (байты совпали) второй раз не копируется (`copied: false`).
- Писатель (редактор, CLI) открывает рабочее состояние одной `Working::load`: `session.json`, иначе `project.json`, плюс история, сверенная с ним; под lock испорченный или раздутый журнал переписывается.
- `Autosave` — чистое состояние: время передаёт вызывающий.
- `save_as`: нет `media/` или `assets/` (git не хранит пустые папки) — в копии пустая папка.
- Переименование — `ProjectDir::rename` (`rename.rs`, без undo): папка `<имя>.devcast` там же; имя по правилам Windows, занятое — отказ, другой регистр — та же папка. Вызывающий держит lock; он снимается до rename (Windows не переименует папку с открытым файлом), свои файлы вызывающий закрывает сам.
- Ошибки по-русски и говорят, что делать.

## Как тестировать

- `cargo nextest run -p dc-project`. Тесты на временных папках с кириллицей и пробелами в путях.

## Куда не лезть

- Модель проекта, команды, undo — `dc-core`. Функции берут путь параметром; общая папка настроек приложения и CLI — `settings::dir()` (`%APPDATA%\DevCast`, там `defaults.json`).
