# dc-media (`crates/media`)

Чтение видеофайлов через FFmpeg (ffmpeg-next): probe, индекс ключевых кадров с кэшем в `cache/` проекта. Дальше — декодер с точным seek (4.3) и кадры-превью (4.4).

## Инварианты

- Время исходника начинается с первого кадра: `SourceTime::ZERO` — наименьший PTS видеопотока (`Probe::first_pts`). Перевод PTS → мкс только через `rescale` (округление FFmpeg).
- `probe` читает пакеты видеопотока без декодирования: число кадров, ключевые кадры (по возрастанию, не пусто), длина = конец последнего кадра − первый PTS, `fps` = кадры / длина.
- Переменная частота: интервалы между кадрами расходятся больше чем на 1 тик шкалы контейнера (Matroska округляет 30 fps до 33/34 мс — это постоянная частота).
- Кэш probe: `cache/<путь медиа>.probe.json`, годен, пока у файла те же размер и mtime. Нечитаемый кэш строится заново (`cache/` можно удалить). Запись атомарная (`dc_project::atomic`).
- Импорт (`import.rs`): только mp4/mov/mkv/webm; копия в `media/<имя>` (занято — `-2`, `-3` …), probe копии сразу идёт в кэш, `MediaKind::Imported`. Всё или ничего: при ошибке скопированное удаляется. `import_dry_run` только читает исходники.
- unsafe нельзя (только capture и encode). FFmpeg-типы наружу не торчат.

## Как тестировать

- `cargo nextest run -p dc-media`. Видео для тестов — `testsrc2` через `.deps/ffmpeg/bin/ffmpeg` во временных папках (`src/test_util.rs`): mp4/mov/mkv/webm, разный GOP, B-кадры, переменная частота. Наша запись — `fixtures/recordings/speech.dcproj` (Git LFS).

## Куда не лезть

- Звук — `dc-audio`. Кодирование и MP4 записи — `dc-encode`. Папка проекта — `dc-project`.
