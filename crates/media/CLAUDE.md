# dc-media (`crates/media`)

Чтение видеофайлов и картинок через FFmpeg (ffmpeg-next): probe, индекс ключевых кадров с кэшем в `cache/` проекта. Программный декодер с точным seek, поток seek с поколениями, пул кадров, кадры-превью.

## Инварианты

- Время исходника начинается с первого кадра: `SourceTime::ZERO` — наименьший PTS видеопотока (`Probe::first_pts`); `Probe::origin_micros` — та же точка в мкс на общих часах файла, от неё считает время и звук (`dc-audio`). Перевод PTS → мкс только через `rescale` (округление FFmpeg).
- `probe` читает пакеты видеопотока без декодирования: число кадров, ключевые кадры (по возрастанию, не пусто), длина = конец последнего кадра − первый PTS, `fps` = кадры / длина. `Probe::color` — единственный источник цветового пространства видео (матрица, диапазон, цветность; без метки — BT.709 limited, слева); другие матрицы — `MediaError::ColorSpace`.
- Переменная частота: интервалы между кадрами расходятся больше чем на 1 тик шкалы контейнера (Matroska округляет 30 fps до 33/34 мс — это постоянная частота).
- Кэш probe: `cache/<путь медиа>.probe.json` (`dc_project::cache`), годен, пока у файла тот же `FileStamp` (размер и mtime). Нечитаемый кэш строится заново (`cache/` можно удалить). Запись атомарная (`dc_project::atomic`).
- Импорт (`import.rs`): только mp4/mov/mkv/webm; копия в `media/<имя>` (занято — `-2`, `-3` …), probe копии сразу идёт в кэш, `MediaKind::Imported`. Всё или ничего: при ошибке скопированное удаляется. `import_dry_run` только читает исходники.
- `Decoder::frame_at(t)` — ровно кадр, показанный в `t` (последний с началом ≤ t; до начала — первый, после конца — последний): seek к ключевому кадру ≤ t, декод вперёд без копирования, копируется только ответ (плотный NV12, отсчёты как в файле: J-форматы не сжимаются в limited) в буфер `FramePool`. Внутри одного GOP вперёд — без seek. `keyframe_at` — ближайший ключевой кадр (пока тянут указатель).
- `FramePool`: лимит байт на все буферы; превышение — `PoolFull`, не рост памяти. Буфер возвращается в пул при drop кадра.
- `Seeker`: декодер на своём потоке (открывается там же: scaler FFmpeg не `Send`), берёт только новейший запрос, ответ несёт поколение; `poll`/`wait` отбрасывают устаревшие.
- Превью (`preview.rs`): первый кадр медиа, вписанный в 320×180 без увеличения (обоснование — в doc модуля), PNG `cache/<медиа>.preview-<байт>-<mtime>.png`; новый файл медиа — новое превью, старое удаляется. NV12 → RGB — фильтр FFmpeg `scale` по `Probe::color`. Превью проекта — превью медиа первого клипа.
- Картинки (`picture.rs`, `decode_picture`): PNG, JPEG, WebP, GIF, анимированные GIF и WebP — все кадры целиком (GIF disposal делает декодер) в RGBA с прямой альфой и длительностью кадра; у неподвижной длительность 0. Все кадры вместе не больше `PICTURE_MAX_BYTES` (512 МБ) — иначе `PictureTooBig`. SVG FFmpeg не читает. Обратно RGBA → PNG — `encode_png` (кадры рендера, эталоны), без потерь.
- Импорт картинок (`picture_import.rs`, `import_picture`): PNG, JPEG, WebP, GIF (SVG — `MediaError::Svg`); файл сначала декодируется, потом копируется в папку проекта (`assets/images` задаёт вызывающий) под своим именем, занято другим файлом — `-2`, `-3` …, тот же файл (байты совпали) не копируется второй раз (`copied: false`). `dry_run` только читает.
- Аппаратного декодирования нет (решение 003, задача 7.34).
- unsafe нельзя (только capture и encode). FFmpeg-типы наружу не торчат.

## Как тестировать

- `cargo nextest run -p dc-media`. Видео для тестов — `testsrc2` через `.deps/ffmpeg/bin/ffmpeg` во временных папках (`src/test_util.rs`): mp4/mov/mkv/webm, разный GOP, B-кадры, переменная частота. Эталон кадра — `reference_frames` (все кадры FFmpeg в NV12 по номеру) и `frame_times` (ffprobe). Картинки — из `color`/`geq` FFmpeg (`picture_tests.rs`, импорт — `picture_import_tests.rs`). Замер seek — `seek_timing` (`--run-ignored only seek_timing --no-capture`). Наша запись — `fixtures/recordings/speech.dcproj` (Git LFS).

## Куда не лезть

- Звук — `dc-audio`. Кодирование и MP4 записи — `dc-encode`. Папка проекта — `dc-project`.
