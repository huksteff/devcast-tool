# dc-encode (`crates/encode`)

H.264, FLAC и AAC через FFmpeg (ffmpeg-next): выбор кодека видео с самопроверкой, кодирование на лету при записи, MP4, кадры сцены в PNG, экспорт MP4 и GIF (gifski), очередь экспорта.

## Инварианты

- Кодек — первый из `Codec::ORDER` (NVENC → QSV → AMF → MF → x264), который прошёл самопроверку и проверку скорости на настоящем размере и fps (`select`, запас ×1,25). Иначе ошибка до старта: `TooSlow` или `NoCodec`.
- Самопроверка (`select::self_test`): серые кадры с паузой, ключевые кадры там, где их просили, программный декодер видит яркость ≈128. Результат кэшируется на процесс; `export_codec` — первый прошедший (строка «Кодирует» диалога экспорта).
- Время — слоты кадров: тик = 1/fps, пропуски разрешены (переменная частота, решение 007). Ключевой кадр (IDR) — первый и первый через ≥ 1 с после предыдущего (GOP 1 с, решение 003). B-кадров нет: порядок декодирования = порядок показа.
- Кадр на входе — `Nv12Frame` (BT.709 limited range, чётные стороны, цветность `left`). Метки цвета BT.709 tv пишутся всегда (решение 006).
- Звук записи (`AudioEncoder::open`): FLAC 16 бит, без задержки кодера: время пакета = номер сэмпла (решение 008). Экспорт — `open_aac`: AAC LC 192 кбит/с, задержку кодера прячет edit list MP4.
- Качество (`Quality`) — постоянное качество кодека; запись — `High`.
- MP4: `Mp4Writer` обычный или фрагментированный (`Mp4Layout::Fragmented` — сегменты записи), одна или несколько дорожек (`with_streams`). `Mp4Reader` читает пакеты без декодирования в нужной шкале тиков.
- FFmpeg-типы наружу не торчат: `Packet`, `StreamParameters`, `Nv12Frame` — свои обёртки.
- Кадр в PNG (`still.rs`): `frame_png` / `sheet_png` рисуют сцену тем же `Compositor`, что превью и экспорт (`Compositor::render_at`). `Sources::feed` подаёт кадры видео и картинки проекта. PNG кодирует `dc_media::encode_png`.
- Экспорт (`export/`): `Timeline` даёт сцену на момент выхода (`dc_ops::Evaluator`, решение 015) и сведённый звук — эффектов экспорт не знает.
- Кадр экспорта n — момент n/fps с округлением до мкс, как `rescale` FFmpeg; кадров `ceil(длительность × fps)`, звук — ровно длительность.
- Цепочка экспорта: `Compositor::draw` → `Nv12Readback` → кодек `open_for_export` (первый из `ORDER` с самопроверкой, без проверки скорости) → `Mp4Writer`.
- `Resolution` — короткая сторона, стороны чётные. fps 30/60, 120 — только если в проекте есть запись ≥ 100 fps.
- GIF (`export_gif`): те же кадры через `Gpu::read` в gifski, fps 15/20/25/30, 720p/1080p/исходный. Размер gifski задаётся явно (иначе он сам уменьшает кадры больше 800×600).
- Пишется в `<имя>.part`, переименовывается в конце: отмена (`ControlFlow::Break` из прогресса) или ошибка не оставляют файла и не трогают старый. Пустое готовое видео — `NothingLeft`.
- `Exported::stages` (`Stages`) — время каждого этапа на потоке экспорта.
- Очередь (`ExportQueue`): один поток, задания (`Job`) по порядку; `cancel` — ждущее не стартует, идущее останавливается на следующем кадре. Паника задания — `Failed`, очередь идёт дальше. `ExportQueue::watched(Watch)` — слушатель каждого изменения задания (старт, кадр, конец), окно будит себя по нему.
- unsafe разрешён здесь с комментарием SAFETY.

## Как тестировать

- `cargo nextest run -p dc-encode`: x264 работает на любом ПК. Основные: `tests/still.rs`, `tests/export.rs` (ffprobe и кадр файла против сцены через ꟻLIP), `tests/gif.rs`, `tests/queue.rs`.
- Аппаратные кодеки проверяет живой тест записи `crates/capture/tests/record.rs`.

## Куда не лезть

- Захват и перевод кадра записи в NV12 на GPU — `dc-capture`; кадра экспорта — `dc_render::Nv12Readback`. Сегменты и manifest — `dc-capture`.
- Сведение звука — `dc-audio` (он зависит от capture → encode, поэтому звук приходит функцией в `Timeline`).
