# dc-render (`crates/render`)

wgpu-компоновщик: видео, SDF-фигуры, blur/glow, текст, спрайты, кисть, motion blur, рендер без окна. Сейчас есть устройство (5.1), `Scene` и `Compositor` (5.2), видеопроход (5.3), SDF-фигуры (5.4); остальные проходы — 5.5–5.11.

## Инварианты

- Один рендер для превью, экспорта и CLI. Одно устройство `Gpu` (instance, adapter, device, queue): окно берёт его клоны, своего не создаёт.
- `Compositor::draw` получает готовую Scene и ничего не решает сам; один render pass на кадр, пайплайны создаются один раз. `Scene` — данные без wgpu (serde, JSON-снимки evaluate): пиксели кадра выхода, кадр начинается чёрным, слои рисуются по `Band` снизу вверх, внутри полосы — в порядке `push`. Камера двигает все полосы, кроме `Overlay`.
- Видео (`Layer::Video`): `Video::fitted` вписывает кроп клипа в кадр без растяжения, по центру. Кадр NV12 (`Nv12::new` проверяет длины плоскостей) отдаётся через `Compositor::upload` до `draw`; сцена с кадром не того времени — `RenderError::NoFrame`. Текстуры кэшируются по `Media::path`, кадр, которого нет в нарисованной сцене, выбрасывается.
- NV12 → RGB в шейдере по `VideoColor` кадра (`Nv12::new`, берётся из `dc_media::Probe::color`): матрица BT.601/709/2020, limited/full range, расположение цветности; R'G'B' пишется через sRGB-вид без изменений байт. Совпадает с `ffmpeg scale` до ±2 (`tests/video_color.rs`).
- Фигуры (`Layer::Shapes`): все фигуры кадра в одном storage buffer, слой — один instanced draw. Прямоугольник со скруглением, эллипс, линия (круглые концы), стрелка (усы ±45° как в v1); заливка цветом или градиентом 2–4 цвета (`cycle` — бесшовная петля, фазу считает evaluate), обводка по краю поверх заливки, `opacity` на фигуру целиком, поворот вокруг центра. Цвета градиента смешиваются в sRGB (как v1 и CSS), сама фигура — в линейном свете. Камера применяется на CPU (центр и все длины).
- Выбор адаптера (`AdapterChoice`): `Auto` — настоящая видеокарта (HighPerformance), без неё программный адаптер (WARP / lavapipe); `Software` — только программный (эталоны CI). Нет никакого — `GpuError::NoAdapter`.
- Бэкенд один на ОС (`BACKEND`, решение 004): Windows — DX12 (и видеокарта, и WARP), macOS — Metal, Linux — Vulkan. Без переопределения через окружение. Эталоны кадров хранятся по бэкенду (`Gpu::info`, решение 012).
- Формат всех кадров и промежуточных текстур — `FORMAT` = `Rgba8Unorm` (egui показывает их без копии). Проходы рисуют и читают через вид `SRGB_VIEW`: смешивание в линейном свете, байты — обычный sRGB (решение 004).
- wgpu ровно та версия, что у egui-wgpu (30): версия задана в корневом `Cargo.toml`.
- Без async-рантайма: futures wgpu ждёт `block::block_on` на текущем потоке.
- `Gpu::read` — плотный RGBA8 без выравнивания строк (`Image`), ждёт отправленную работу.

## Как тестировать

- `cargo nextest run -p dc-render`. `tests/gpu.rs`: устройство `Auto` и `Software` создаётся, проход очищает текстуру 67×5 (строки с выравниванием) в цвет, кадр сверяется побайтно. `tests/draw.rs`: пустая сцена — чёрный кадр, sRGB-вид пишет линейные 0,5 байтом 188. `tests/video.rs`: цвета BT.709, поля, кроп, камера, цветность слева, ошибки кадра (NV12 строит `tests/common`). `tests/video_color.rs`: синтетика FFmpeg BT.601/709 × limited/full через `dc-media` против RGB FFmpeg. `tests/shapes.rs`: пиксели внутри, снаружи и на краю каждой фигуры, обводка, прозрачность, поворот, градиенты, камера, порядок полос. На CI без видеокарты оба теста идут на WARP.
- `--no-capture` печатает выбранный адаптер.

## Куда не лезть

- Окно, surface и egui — `dc-app`. Декодирование — `dc-media`, кодирование — `dc-encode`.
- Что рисовать — `evaluate` эффектов (`fx/*`), здесь только рисование.
