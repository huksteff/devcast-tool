# dc-cli (`crates/cli`)

Бинарник `devcast`: монтаж, анализ, рендер кадров и экспорт из командной строки. Логика в библиотеке (`run`), `main.rs` только печатает `Outcome`.

## Инварианты

- `run(args, cwd, registry) -> Outcome` — чистый вход для тестов: код выхода, stdout, stderr. stdout — только результат, stderr — ошибки и предупреждения. Коды: 0 готово, 1 не получилось (`CliError::Failed`), 2 неверная командная строка (`CliError::Usage`).
- Глобальные флаги `--project`, `--json`, `--dry-run` снимаются со всей строки (`globals::split`); поля команд с такими именами запрещает реестр `ops`.
- Встроенные команды — подкоманды clap (`builtin.rs`, группы вроде `clip add`, `zoom suggest`, `captions gen` — `builtin_groups.rs`), остальное — команда реестра `dc_ops::Registry::devcast()` (общий с редактором), её аргументы разбирает `dc_ops::parse_args`.
- Справка (`help.rs`) собирается из тех же определений: у встроенной команды `about`, `after_help` (пример), `help` аргументов; у команды `ops` — `ABOUT`, `EXAMPLE` и JSON Schema из doc-комментариев. `help --json` отдаёт ещё схему `Project` и состояний эффектов.
- Проект: `--project`, иначе папка `*.devcast`, внутри которой стоим, иначе единственная `*.devcast` в текущей папке. Без редактора CLI — единственный писатель (lock); правит `session.json`, если есть несохранённое редактора, иначе `project.json`. Событие истории пишется до файла проекта. Проект держит редактор (`lock-owner.json` — `dc_ops::live::LOCK_OWNER`) — `live.rs` (7.32): `Open` по каналу программы (`Local::app_channel`), редактор пишет рабочее состояние на диск, команда идёт тем же кодом, события истории — `Write` в редактор (берёт, только если его ревизия не сменилась); программы нет — файлы.
- Открытие проекта (`Workspace::open`) восстанавливает записи убитого процесса записи, если lock свободен (решение 007); под `--dry-run` только предупреждение.
- Короткий вывод по умолчанию (`Applied` одной строкой), `--json` по запросу; ошибка под `--json` — `{"error", "code"}` в stderr. Дроби в тексте — до 3 знаков (`round.rs`), числа целиком — только в JSON.
- Правка (`edit.rs`): команда `ops` и `apply plan.json` — одна запись истории через `edit::apply_steps`; сокращения, которые понимает только CLI, работают и в команде, и в шаге плана (`dc_ops::build_with`): `cut w12-w20` (`transcript::word_args`) и `zoom add --at clicks` (`autozoom::clicks` → `dc_ops::autozoom::expand`, общий с редактором). `undo [n]`/`redo` идут по `History` и пишутся событиями `history.jsonl`; `save` переносит `session.json` в `project.json`. `rename <имя>` (`rename.rs`) — `ProjectDir::rename` под lock, без истории; проект держит редактор — `Request::Rename` (переименовывает он). Под `--dry-run` всё в памяти, без lock и записи.
- Команды, которым сначала нужны файлы (`new`, `clip add`, `image set`, `audio add`, `captions gen/import`), готовят их и применяют свои команды через `edit::apply_commands` — одна запись истории; у `clip add`, `image set` и `audio add` ошибка команды удаляет сделанные копии, у `new` (`dc_ops::new_project`) — папку проекта.
- Проект целиком (`builtin_project.rs`): `discard` — `Request::Discard` редактору, без него `Working::discard` под lock; `close [--save|--discard]` — `Request::Close`, несохранённое без флага — отказ; `save --as` — копию делает CLI из рабочего состояния, редактору — `Request::Copied` (сверка ревизии, отказ — копия удаляется); `trash [--restore]` — `dc_project::bin`; `new --each` — `dc_ops::new_projects`.
- `font add|ls` (`font.rs`): копия шрифта в `assets/fonts/` через `dc_ops::import_font` под lock, без записи истории; проект держит редактор — `Request::Fonts` (он перечитывает списки).
- Стиль (`style.rs`): `set ключ.аргумент=значение …` — команды настроек эффектов (`Op::SETTINGS`) одной записью `set`; `style copy` — `Defaults::restyle`. `defaults show|set|from-project|reset` (`defaults.rs`): файл — `Ctx::defaults_file`. Программа (`builtin_program.rs`, `builtin_app.rs`): `config`, `hotkeys` — правка `dc_settings::Edit` запущенной программе (`Request::Settings`), без неё — в файл (`app_settings.rs`); `models` (прогресс — `Local::progress`); `ls projects`; `app status|show|quit`, `captions stop` — запросы программе; `app feedback|changelog` — `dc_update`.
- «Сделать красиво»: `beautify` (`beautify.rs`) — нейронка `dc-agent` в папке проекта, под `DEVCAST_GROUP` (`bounds.rs`): закрытые команды — `not_for_agent`, `--project` — только свой, `-o` — в проект или temp; `recipes` — `Edit::Ai`, как `config`; `DEVCAST_GROUP` (`Local::group`) — правки запуска одним шагом (`History::group`); тесты — нейронка `.cmd` (`Local::agent`). Папка настроек — `Local::settings` (тесты дают свою). `captions gen`, `transcript`, `cut w…` без флагов — `captions.*` настроек (`speech::chosen`).
- `batch <проекты…> -- <команда>` (`batch.rs`): `*` и `?` раскрывает сам CLI; команда проверяется один раз до проектов; каждый проект — как с `--project`, своя запись истории; ошибка проекта — предупреждение и код 1; запрещённые команды — `Cli::not_for_batch`. Время в `info`, `ls`, `events`, `transcript`, `silences` — выходное, вырезанное только считается.
- Слова (`transcript.rs`, `speech.rs`): каждая запись распознаётся целиком один раз (`speech::project_words`, кэш в `cache/`); id слов `w1, w2, …` — по порядку записей и времени в записи, вырез их не меняет. В `cut` границы слов сдвигаются к самому тихому месту в пределах 150 мс (решение 010), сошлись — свои (`cut_bounds`). `captions gen` — только невырезанные слова. Whisper линкует только этот крейт (решение 018).
- Процесс распознавания редактора (`worker.rs`): `devcast --captions-worker` (единственный аргумент, его проверяет `main.rs`, в справке нет) читает `dc_ops::recognition::Request` из stdin и пишет строки `Message`; путь — `speech::generate`, как у `captions gen`.
- Автозумы (`autozoom.rs`): предложения — `dc_ops::click_zooms` (общие с редактором). Запись, добавленная в проект (стоп `record`, восстановление), идёт через `dc_ops::autozoom::after_recording` (тот же путь у записи из программы): автозумы одной записью, если `zoom.auto`; ошибка — предупреждение.
- `record` (`record.rs`, решение 011): процесс записи сам пишет проект и до старта занимает канал `devcast-record-<пользователь>` (`record_control::Server`); `record stop|pause|resume|cancel` шлёт туда `Control` и ждёт ответа; процесса нет — записи программы (`record_app.rs`, `Request::RecordControl`); `record --app` — `Request::Record`, ответ после первого кадра. Ctrl+C и закрытие консоли — тот же стоп. Имя канала — параметр, тесты берут своё.
- `export` (`export.rs`, решение 011): вызов отдаёт снимок проекта в очередь `dc_encode::ExportQueue` процесса с каналом `devcast-export-<пользователь>`; канала нет — вызов сам становится очередью; проект держит редактор — очередь программы (`export_app.rs`, id `p2`), `status`/`cancel` — обе. Сцена `export`, `frame`, `sheet` готовится одной `scene.rs`; звук — `dc_ops::sound::levels`.
- `skill install` (`skill.rs`) кладёт вшитый `skill/SKILL.md` в `~/.claude/skills/devcast/`; `skill_tests` прогоняет его примеры и ищет в нём каждую команду: правь SKILL.md.

## Как тестировать

- `cargo nextest run -p dc-cli`. Тестовые проекты — `src/test_util.rs`: `Fixture` (пустой проект, команды `test add/rm`, путь с кириллицей и пробелами) и `Recordings` (две записи, настоящий реестр, синтетическая телеметрия).
- Сценарии по файлам `src/*_tests.rs`; e2e одним insta-снимком — `e2e_tests.rs`, `scope_e2e_tests.rs`, `pauses_e2e_tests.rs` (после намеренной смены вывода — `INSTA_UPDATE=always` и просмотр diff; размер вывода — решение 014).
- `tests/binary.rs` — настоящий exe; `tests/worker.rs` — `--captions-worker`; `#[ignore]` — живая запись (`tests/record_live.rs`) и настоящий Whisper.

## Куда не лезть

- Разбор аргументов, планы, dry-run, вывод diff — `dc-ops`. Файлы проекта, lock, история на диске — `dc-project`. Сами команды — `fx/*`.
