# dc-cli (`crates/cli`)

Бинарник `devcast`: монтаж, анализ, рендер кадров и экспорт из командной строки. Логика в библиотеке (`run`), `main.rs` только печатает `Outcome`.

## Инварианты

- `run(args, cwd, registry) -> Outcome` — чистый вход для тестов: код выхода, stdout, stderr. stdout — только результат, stderr — ошибки и предупреждения. Коды: 0 готово, 1 не получилось (`CliError::Failed`), 2 неверная командная строка (`CliError::Usage`).
- Глобальные флаги `--project`, `--json`, `--dry-run` снимаются со всей строки (`globals::split`), поэтому стоят где угодно. Поля команд с такими именами запрещает реестр `ops`.
- Встроенные команды — подкоманды clap (`Builtin` в `builtin.rs`, группы вроде `clip add`, `defaults show` — `builtin_groups.rs`), всё остальное — команда из реестра `ops` (`external_subcommand`), её аргументы разбирает `dc_ops::parse_args`.
- Справка (`help.rs`) собирается из тех же определений: у встроенной команды `about` = строка списка, `after_help` = пример (без `devcast`), `help` у аргументов; у команды `ops` — `ABOUT`, `EXAMPLE` и JSON Schema (doc-комментарии полей = описания). `help --json` отдаёт ещё схему `Project` и состояний всех эффектов.
- Проект: `--project`, иначе папка `*.dcproj`, внутри которой стоим, иначе единственная `*.dcproj` в текущей папке.
- Без редактора CLI — единственный писатель (lock). Правит рабочее состояние: `session.json`, если редактор оставил несохранённое, иначе сразу `project.json`. Событие истории пишется до файла проекта.
- Короткий вывод по умолчанию (`Applied` одной строкой), `--json` по запросу; ошибка под `--json` — `{"error", "code"}` в stderr.
- Команды правки (`edit.rs`): команда `ops` и `apply plan.json` — одна запись истории; `undo [n]`, `redo` идут по `History`, на диск пишутся событиями `history.jsonl`; `save` переносит `session.json` в `project.json`. Под `--dry-run` всё делается в памяти без lock и записи. Стиль (`style.rs`, «Задача 5.38»): `set ключ.аргумент=значение …` — команды настроек эффектов (`Op::SETTINGS`, `dc_ops::settings_commands`: значения проверяет сама команда) одной записью истории `set`; `style copy --from --to <проекты…>` — `Defaults::restyle` (настройки всех эффектов как у источника, содержимое не трогается) командой `style copy` в каждом проекте. `defaults show|set|from-project|reset` (`defaults.rs`): файл — `Ctx::defaults_file` (тесты дают свой через `run_with` и `Local`, настоящий `%APPDATA%` не трогают); `set` — те же команды настроек на проекте без клипов из умолчаний; `show` — аргументы команд настроек, отличные от заводских, строками `ключ.аргумент=значение` для `set` (`EffectInfo::settings_args`); автозумы после записи — `zoom.auto`. `batch <проекты…> -- <команда>` (`batch.rs`): проекты — папки `*.dcproj`, `*` и `?` в последней части пути раскрывает сам CLI (оболочки Windows не раскрывают); команда разбирается и имя/аргументы команды `ops` проверяются один раз до проектов; каждый проект — как с `--project`, своя запись истории; ошибка проекта — предупреждение и код 1 (`Answer::code`), остальные идут; нельзя команды без проекта, создающие проект, перечисляющие проекты и пишущие один `-o` (`Cli::not_for_batch`).
- `info` и `ls <список>` (`ls.rs`): списки — `clips` и `Effect::LISTS` эффектов; время объектов — выходное (`TimeMap::output_span`), вырезанные объекты в конце с пометкой «вырезан». Фильтры `--from/--to` по пересечению, `--fields`, страницы `--limit/--offset` с подсказкой следующей. Вложенный объект в тексте — поля через точку (`focus.x=0.5`), дроби в тексте — до 3 знаков (`round.rs`), JSON (числа целиком) только под `--json`.
- `transcript` (`transcript.rs`): каждая запись проекта распознаётся целиком один раз (`speech::project_words`, кэш в `cache/`), дорожка как у `silences` (`speech::pick`); id слов `w1, w2, …` — по порядку первых клипов записей и времени внутри записи, поэтому вырез их не меняет. Слова и реплики — по выходному времени, вырезанное только считается. `cut w12-w20,w31` (`transcript::word_args`, в команде и в шаге плана — `edit::apply_steps` через `dc_ops::build_with`): id слов заменяются выходными временами от начала первого до конца последнего, границы сдвигаются к самому тихому месту в пределах 150 мс (`dc_audio::silence::quietest`); нужны слова, уже распознанные `transcript` (модель fast, язык авто).
- `captions` (`captions.rs`) — группа clap: `gen`, `export`, `import` встроенные, остальные `captions …` уходят в реестр. `gen` — `speech::generate` (общий с процессом распознавания редактора: записи как у `transcript`, каждая дорожка `--tracks`, слияние `merge_tracks`, пусто — «речи не найдено») и `CaptionsGen` одной записью истории. Whisper линкует только этот крейт (решение 018): `speech.rs` переехал сюда из dc-ops (`project_words`, `media_cues`, `pick`, `generate`; прогресс — `OnProgress`, доля 0..1 всех записей и дорожек). `import` читает файл и ставит `CaptionsImport`; `export` под `--dry-run` файл не пишет. Процесс распознавания редактора (`worker.rs`, решение 018): `devcast --captions-worker` (единственный аргумент, проверяет `main.rs` до `run`: ответ идёт строками по ходу работы, а не `Outcome`; в справке нет) читает `dc_ops::recognition::Request` из stdin и пишет строки `Message` в stdout: проценты, затем `cues` или `error` (паника — тоже `error`); закрытый stdout — выход. Путь — `speech::generate`, как у `captions gen`. Редактор ищет `devcast.exe` рядом со своим exe.
- `silences` (`silences.rs`, аргументы — clap `Args`): поиск в `dc_audio::silence` по каждому сегменту карты времени в его записи (дорожка `mic`, у импортированного видео — первая), паузы по обе стороны выреза или стыка клипов склеиваются, `--min` — по выходному времени.
- `events <clicks|keys|activity>` (`events.rs`; чтение телеметрии записей — `telemetry.rs` поверх `dc_capture::project::recorded`): время выходное (`TimeMap::locate`), вырезанное не показывается, только считается; точки — доли кадра клипа после кропа (`Rect::to_local`); activity — отрезки ввода с паузами ≤ 1 с.
- Автозумы (`autozoom.rs`): `zoom` — группа clap: `zoom suggest` встроенная, остальные `zoom …` уходят в реестр, но `zoom add --at clicks` (только с `--scale`, `--mode`; в команде и в шаге плана — `autozoom::clicks`) ставит предложения `dc_ops::click_zooms` (общие с редактором) пачкой `ZoomAdd` — одна запись истории. Запись, добавленная в проект (стоп `record` и восстановление в `Workspace::open`), идёт через одну `after_recording(workspace)`: автозумы одной записью истории, если `settings.auto` зума; ошибка — предупреждение, запись цела; под `--dry-run` восстановления нет, значит и автозумов.
- `record` (`record.rs`, аргументы — `record_args.rs`, решение 011, «Задача 3.15»): процесс записи сам пишет проект (`dc_capture::win::ProjectRecording`) и до старта захвата занимает канал `dc_ipc` `devcast-record-<пользователь>` (`record_control::Server`); `record stop|pause|resume|cancel` из другого вызова шлёт туда `Control` и печатает ответ (`Reply`), который приходит, когда запись это сделала. `--duration` — секунды записи без пауз (таймер `recv_timeout` очереди запросов). Под `--dry-run` ничего не пишется и канал не трогается. Ctrl+C и закрытие консоли — тот же запрос стопа (`Server::stopper` → `on_console_stop`). `ls sources` (`sources.rs`) — мониторы, окна, микрофоны; проект не нужен.
- Открытие проекта (`Workspace::open`) восстанавливает записи убитого процесса: если lock свободен, собирает их и дописывает клип в рабочее состояние (под `--dry-run` только предупреждение, ничего не пишется), по строке предупреждения на запись (решение 007, «Ctrl+C и убитый процесс записи»).
- `new <video...> -o x.dcproj` и `clip add <video...>` (`import.rs`): видео копируются в `media/` (`dc_media::import`, под `--dry-run` только probe), клипы добавляет команда `dc_fx_cut::ClipAdd` через `dc_ops::apply_commands` — одна запись истории; у нового проекта история пуста, при ошибке его папка удаляется. `clip` — группа clap: `clip add` встроенная, остальные `clip …` уходят в реестр; в справке группа раскрывается в `clip add`. В `ls clips` поле `kind` (recording/imported).
- `image set <id> --file <картинка> [--at t]` (`image.rs`): `image` — группа clap без команд реестра; картинка читается и копируется в `assets/images/` (`dc_ops::import_picture`, общий с редактором, под `--dry-run` только читается), затем `dc_fx_image::ImageSet` через `apply_commands` — одна запись истории; ошибка команды удаляет сделанную этим вызовом копию.
- `audio add <файл> --at t [--track n] [--duration s]` (`audio.rs`): `audio` — группа clap, остальные `audio …` (`channel`, `mute`, `reset`, `set`, `rm`) уходят в реестр; файл читается целиком и копируется в `assets/audio/` (`dc_audio::import_sound`, под `--dry-run` только читается), затем `AudioAdd` одной записью истории; ошибка команды удаляет сделанную копию.
- `export` (`export.rs`, аргументы — `export_args.rs`, задание — `export_job.rs`, очередь между вызовами — `export_queue.rs`, решение 011, «Задача 5.14»): вызов снимает рабочее состояние проекта (`Spec`) и отдаёт его в очередь `dc_encode::ExportQueue` процесса, который держит канал `devcast-export-<пользователь>`; канала нет — этот вызов сам становится очередью и живёт, пока она не опустеет; тесты дают свой канал (`Local::export_channel` в `run_with`). Ответ приходит, когда готов свой файл. В JSON ответа — `stages`: время этапов экспорта, с (`dc_encode::export::Stages`). `export status` — задания с прогрессом и оценкой остатка, `export cancel [eN]` — отмена (без номера — всех), Ctrl+C процесса очереди отменяет всё. Формат — по расширению `-o` или `--format`, путь печатается без `..`. Подготовка сцены (телеметрия, встроенные шрифты `TextMeasure` и `Compositor`) — общая `scene.rs` для `export`, `frame` и `sheet`. `frame --at t [--grid] [--width w] -o f.png`, `sheet [--from] [--to] -n 6 [--width w] -o s.png` (`still.rs`): сцены `Evaluator`, PNG `dc_encode::frame_png` / `sheet_png` (`--width` — ширина PNG: кадр рисуется уменьшенным, как экспорт в своём разрешении, `Compositor::render_at`; у раскадровки — вся ширина с полями), картинки проекта подаёт `Sources`; кадры раскадровки — начала n равных частей отрезка, столбцов ⌈√n⌉; сетка (`grid.rs`) — линии через 0,1 кадра с подписями в `Band::Overlay`; под `--dry-run` GPU не нужен, файл не пишется. Сцена — `dc_ops::Evaluator` с телеметрией курсора записей (`telemetry::tracks`: курсор и сочетания клавиш; запись без manifest — ошибка), звук — `dc_audio::Mixer` с уровнями и доп. звуком `fx/audio-tracks` (`dc_ops::sound::levels`: `dc_fx_audio_tracks::sound` → `dc_audio::Levels`, путь файла — от папки проекта).
- Реестр — `dc_ops::Registry::devcast()` (общий с редактором); новый эффект регистрируется там (`crates/ops/src/devcast.rs`): его `ops()` в список команд и `effect()`, если у него есть состояние. Команда, которая меняет только настройки эффекта, объявляет `Op::SETTINGS` — ключ для `set` и `defaults set`.
- `skill install` (`skill.rs`) кладёт `skill/SKILL.md` (вшит через `include_str!`) в `~/.claude/skills/devcast/`. Строки `devcast …` в блоках кода SKILL.md и JSON-план оттуда `skill_tests` прогоняет подряд (рядом с проектом лежат картинка `логотип.png` и звук `музыка.mp3`): меняешь команды или их аргументы — правь SKILL.md.

## Как тестировать

- `cargo nextest run -p dc-cli`. Тестовые проекты — `src/test_util.rs`: `Fixture` (пустой проект, тестовые команды `test add/rm`, папка с кириллицей и пробелами) и `Recordings` (две записи, настоящий реестр). Сценарии — `src/tests.rs`; `src/edit_tests.rs` — apply/undo/redo/history/save; `src/ls_tests.rs` — info/ls на настоящем реестре; `src/events_tests.rs`, `src/autozoom_tests.rs` — events и автозумы на синтетической телеметрии (`Recordings::with_telemetry`), автозумы фикстуры `clicks.dcproj` = проект `dc_ops::click_zooms`; `src/skill_tests.rs` — примеры SKILL.md и установка в временную папку; `src/style_tests.rs` — set, defaults, style copy, batch; `src/still_tests.rs` — frame (аннотации и картинка в PNG, сетка, `--width`; кадр `frame` = кадр MP4 `export` в тот же момент по яркости с точностью до шума кодека) и sheet на копии `clicks.dcproj` (`test_util::fixture_copy`); `src/recover_tests.rs` — восстановление убитой записи на синтетических сегментах; `src/record_tests.rs` — аргументы записи, dry-run, канал управления без записи на своём имени `test-record-<pid>` (настоящий `devcast-record-<пользователь>` не трогается: имя канала — параметр `Server::start` и `send`, настоящее задаёт `record`), `ls sources`; `tests/record_live.rs` (`#[ignore]`, `DEVCAST_TEST_MONITOR`) пишет экран через exe; `src/image_tests.rs` — image set (копия, undo, GIF и ключ, отказы, dry-run); `src/audio_tests.rs` — audio add (копия, место по выходу после выреза, отказы, dry-run), уровни по умолчанию и свои, разрезанный клип, вход микшера; `src/import_tests.rs` — new/clip add на видео `testsrc2` (`test_util::test_video`, ffmpeg из `.deps` — `test_util::ffmpeg`); `src/transcript_tests.rs` — transcript и cut по словам на речи `fixtures/audio/tts-ru.flac`; `src/captions_tests.rs` — captions на той же речи; `src/silences_tests.rs` — silences на копии `fixtures/recordings/speech.dcproj`; `src/pauses_e2e_tests.rs` — e2e 4.18 одним insta-снимком; `src/e2e_tests.rs` — весь сценарий агента одним insta-снимком (после намеренной смены вывода — `INSTA_UPDATE=always cargo nextest run -p dc-cli e2e` и просмотр diff снимка; размер вывода — docs/decisions/014-cli-output.md); `src/scope_e2e_tests.rs` — сценарий SCOPE 5.39 (паузы, автозумы, аннотация, субтитры, раскадровка, экспорт; 14 вызовов) одним снимком на копии `clicks.dcproj` с дорожкой `mic` из `tts-ru.flac` и словами в кэше, затем MP4: длительность как у `info`, уровень речи как у файла, кадры против записи (`scope_e2e_frames.rs`: подпись, реплика, зум срезает рамку окна); `src/cut_e2e_tests.rs` — экспорт после стыка, 10 вырезов и 2×: вспышки и писки видео ffmpeg на своих местах по `TimeMap`; `src/export_tests.rs` — аргументы, dry-run, status/cancel и два экспорта сразу через одну очередь на своём канале `test-export-*` (настоящий не трогается); `tests/binary.rs` проверяет настоящий exe (коды выхода, stdout/stderr); `tests/worker.rs` — `--captions-worker` через exe (испорченный запрос, проект без записей — «речи не найдено»; `#[ignore]` — настоящий Whisper на копии `speech.dcproj`, нужна модель «Быстрая» в `%APPDATA%DevCastmodels`).

## Куда не лезть

- Разбор аргументов команд, планы, dry-run, вывод diff — `dc-ops`. Файлы проекта, lock, история на диске — `dc-project`. Сами команды — `fx/*`.
