# dc-app (`crates/app`)

Бинарник devcast-app: HUD, окна записи, редактор, таймлайн, библиотека, настройки. Логика в библиотеке (`run`), `main.rs` только печатает ошибку.

## Инварианты

- Один экземпляр на пользователя (`instance.rs`): первый держит канал dc-ipc `devcast-app-<пользователь>`, второй запуск просит его показаться и выходит.
- Журнал (`logging.rs`): `%APPDATA%\DevCast\logs\devcast-app.*.log`, ротация раз в сутки, хранится 7 файлов, паника пишется в журнал с backtrace. `RUST_LOG` задаёт уровень.
- Дампы падений (`crash.rs`, единственный `unsafe` dc-app): при старте запускается копия программы с `--crash-server`, падение пишет minidump в `%APPDATA%\DevCast\crashes`; если запись дампов не запустилась — ошибка в журнале, приложение работает.
- Окна рисует wgpu на одном бэкенде `dc_render::BACKEND` (DX12 на Windows, `gpu.rs`, решение 004): по умолчанию eframe брал Vulkan, и закрытие поповера роняло debug-сборку (swapchain Vulkan у NVIDIA на DXGI освобождался, пока GPU его читал).
- Перерисовка только по событию (решение 002): безусловный `request_repaint()` запрещён, анимации — `request_repaint_after`. Потоки (уровни, превью, запись, трей, горячие клавиши, второй запуск) будят только главное окно (`request_repaint_of(ROOT)`), а оно в своём проходе передаёт перерисовку показанным поповеру и настройкам (`app::show_windows`): `request_repaint_of` окна, которого нет, заставляет egui открыть пустое окно «egui window» по умолчанию. Кадр любого другого окна идёт через `app::other_window`: после клика или клавиши, или если кадр открыл или закрыл окно либо сдвинул запись, он будит главное окно (только его кадр открывает и закрывает окна).
- eframe собран с `inspection` + `accesskit`: `EGUI_INSPECTION=1` открывает порт для egui-mcp (`.mcp.json`, решение 012), без переменной инспекция выключена.
- Настройки (`settings.rs`) — один файл `%APPDATA%\DevCast\settings.json` и один `Store` на все окна (`app::Shared` за `Arc<Mutex>`): HUD и окно настроек правят одно и то же. Каждое изменение пишется сразу и атомарно (`Store::update`, без изменений — без записи); поля, которых нет в файле, берут умолчания; испорченный файл — ошибка с советом удалить его. Модель Whisper — `SpeechModel` (`fast`/`accurate`, как `--model` CLI).
- Окна кроме главного — deferred viewports (решение 002) с общим `Shared`. Окно настроек (`settings_window.rs`): открывается по центру монитора HUD (`app::on_hud_monitor`, как редактор), разделы слева, изменения сразу, без «Сохранить»; выбор fps и отсчёта — общие функции `fps`/`countdown` с HUD; строки — `settings_rows.rs` (подпись и элемент по центру строки, линия под строкой); модели Whisper (`models.rs`): «Скачана» по файлу в `dc_transcribe::models_dir`, «Скачать» — `dc_transcribe::ensure` на своём потоке с прогрессом, будит главное окно, закрытие окна отменяет загрузку (`.part` докачается).
- HUD (`hud/`) — главное окно (решение 001): без рамки и без тени winit (`set_undecorated_shadow(false)` в `lib.rs`, иначе сверху светлая строка заголовка 1 px), поверх всех, без кнопки на панели задач; Win32 (скругление регионом окна по радиусу 12 точек, исключение из захвата по «Скрывать HUD», место в физических px) — `dc_capture::win::hud_window` (unsafe только там). Окно подгоняется под ширину полосы. Место — на каждом мониторе отдельно (`placement.rs`, ключ — прямоугольник монитора), новый монитор — внизу по центру; сохраняется, когда окно сдвинулось и кнопки мыши отпущены. Перетаскивание — `StartDrag` с ручки.
- Поповеры HUD (`hud/popover.rs`) — одно окно (deferred viewport) за раз над полосой в 8 px, исключено из захвата вместе с HUD по «Скрывать HUD» (`ViewportCommand::ContentProtected`: нет в записи, в стоп-кадре области и в превью), по размеру содержимого: содержимое раскладывается в полной высоте поповера (`MAX_HEIGHT` 620, дальше прокрутка), а не в текущей высоте окна; ширина «Звука» — под самое длинное имя устройства (300…460), длиннее — сокращение в середине; у каждого поповера свой заголовок окна (`Kind::title`); Esc или потеря фокуса закрывают, но фокус считается потерянным только после того, как окно его получило (окно, открытое из-за другой программы, например через UI Automation, Windows не активирует). Другие окна закрываются до старта записи.
- Поповеры «Звук» и «Частота кадров / отсчёт» (`hud/menus.rs`) правят тот же `Store`; клик по микрофону выбирает его, поповер остаётся. Индикаторы уровня (`meters.rs`): `LevelMeter` на источник открыт, только пока его показывают (все — пока открыт «Звук», выбранный микрофон — пока открыты настройки или идёт запись); каждый уровень будит главное окно; уровень старше 0,3 с считается тишиной.
- Выбор источника (`hud/picker.rs`): поповер 720 px, карточки 4 в ряд, экраны и не свёрнутые окна; превью снимает поток по одному (снимок GDI без жёлтой рамки, `dc_capture::win::preview_*`) и будит UI; выбор пишется в `Store` сразу, выбранное окно выходит на передний план; под экраном — разрешение и масштаб Windows (`MonitorInfo::scale`).
- Выбор области (`area/`, решение 001): окно без рамки размером с монитор на каждом мониторе (прямоугольник монитора в точках главного окна; `fullscreen` winit нельзя — DXGI не создаёт swapchain для такого окна, программа падала), фон — стоп-кадр монитора; рамка в физических px монитора (`model.rs`): стороны чётные, минимум 150, пресеты «16:9» и «1080p» (только двигается, гаснет на мониторе меньше); ручки ловятся в 18 px; Enter/«Начать запись» пишет область в источник и `last_area`, Esc/«Отмена» ничего не меняет. Открывается карточкой «Область…» выбора источника с последней областью.
- Запись (`session.rs`, `recorder.rs`): состояния покой → отсчёт → `Launch` (окна закрываются за кадр до старта) → старт → запись → подготовка/отмена → покой. `ProjectRecording` живёт на потоке `devcast-recorder` от старта до конца; UI только шлёт `Request` и берёт `Event` (каждое будит UI), сам не ждёт. Таймер — часы рекордера (QPC минус паузы из событий). Пока висит «Отменить запись?», запись на паузе; закрытие вопроса любым способом — «Продолжить запись». Выход из программы (`on_exit`) останавливает и сохраняет запись. Отсчёт (`countdown.rs`) — окно 200 × 200 по центру записываемого, всегда исключено из захвата.
- Значок DevCast (`logo.rs`) рисуется кодом: трей и `with_icon` каждого окна; у окон один и тот же `Arc` (egui заново шлёт значок окну, если `Arc` другой).
- Трей (`tray.rs`) живёт в `App` (главный поток): действия меню и клика приходят каналом и будят UI, вид меню (`TrayView` из `Shared::tray_view`) применяется только при изменении. Левый клик — показать HUD, правый — меню.
- Глобальные горячие клавиши (`hotkeys.rs`) живут в `App` (главный поток), как трей; сочетания хранятся текстом `Ctrl+Shift+R` по физической клавише; перерегистрируются только при изменении; пока окно настроек ловит сочетание, глобальные сняты. Не зарегистрированные — `Shared::taken_hotkeys`, их показывает раздел «Горячие клавиши» (`settings_hotkeys.rs`).
- После стопа (`Event::Stopped`) открывается `editor.rs` с проектом по центру монитора HUD (`HudPlacement::monitor`), HUD прячется; закрытие редактора показывает HUD. Ошибка подготовки — поповер `Kind::Failed` с папкой записи. `hud::bar_ui` — весь HUD без родного окна: им E2E (`e2e_tests.rs`, `#[ignore]`, пишет экран) ведёт запись кликами.
- Любое действие UI с проектом — команда из реестра dc-ops. Строки интерфейса — из dc-ui-kit.

## Как тестировать

- `cargo nextest run -p dc-app`: логика окон и снимки egui_kittest (`tests/snapshots`, тесты окон — `*_tests.rs` рядом с кодом, настройки — во временной папке).
- Живой прогон: `EGUI_INSPECTION=1 cargo run -p dc-app`, затем egui-mcp (`attach`, `widget_tree`, `screenshot`). Из Claude desktop (пакет MSIX) запущенная программа получает виртуальный `AppData`, и сокет дампов падений там не работает (ошибка 10022 в журнале): запись дампов проверять, запуская через `explorer.exe <путь к exe>`.
