# dc-app (`crates/app`)

Бинарник devcast-app: HUD, окна записи, редактор, таймлайн, настройки. Логика в библиотеке (`run`), `main.rs`: хуки Velopack, ошибка.

## Инварианты

- Один экземпляр на пользователя (`instance.rs`, канал dc-ipc `devcast-app-<пользователь>`, `dc_ops::live`); правка из CLI — `editor/live.rs` (`Document::take`). Журнал — `logging.rs` (`%APPDATA%\DevCast\logs`, `RUST_LOG`); дампы (`crash.rs`, единственный `unsafe`) и паники — в `logs\crashes`, отчёт и «Что нового» — поповеры старта (`hud/notices.rs`).
- Распознавание речи — процесс `devcast --captions-worker` рядом с exe (решение 018): dc-app не линкует whisper и Vulkan (dc-transcribe запрещён `xtask verify`), отмена — убийство процесса (`recognition/job.rs`), протокол — `dc_ops::recognition`.
- GPU одно: `dc_render::Gpu` (`gpu.rs`) создаётся до eframe, eframe получает его клоны (`WgpuSetup::Existing`); бэкенд — `dc_render::BACKEND` (DX12, решение 004).
- Перерисовка только по событию (решение 002): безусловный `request_repaint()` запрещён, анимации — `request_repaint_after`. Потоки будят только главное окно (`request_repaint_of(ROOT)`), оно передаёт перерисовку открытым окнам (`app::show_windows`): `request_repaint_of` несуществующего окна открывает пустое окно egui. Кадр другого окна идёт через `app::other_window`.
- Настройки (`settings.rs`, модель и файл — dc-settings): один `%APPDATA%\DevCast\settings.json` и один `Store` на все окна (`Shared`, `Arc<Mutex>`); изменение пишется сразу и атомарно (`Store::update`), недостающие поля — умолчания. `devcast config`/`hotkeys` — `Request::Settings` (`editor/live.rs`: `dc_settings::apply` через тот же `Store`; окна видят в следующем кадре, глобальные клавиши перерегистрируются в том же проходе); `ls projects` — `Request::Current`. Язык и дорожки субтитров — там же (окно настроек и панель субтитров). «По умолчанию» (`settings_defaults.rs`) — файл `devcast defaults` теми же вызовами `dc_project::Defaults`.
- Окна кроме главного — deferred viewports с общим `Shared`. Окна без рамки строит `borderless::window` (без тени, решение 019); HUD, поповеры и отсчёт — прозрачные `borderless::floating` (решение 020), панель и тень рисует egui; непрозрачные окна заливают себя `app::opaque`.
- HUD (`hud/`) — главное окно, поверх всех; исключение из захвата и место в физических px — `dc_capture::win::hud_window` (unsafe только там); место своё на каждом мониторе (`dc_settings::placement`). Поповеры (`hud/popover.rs`) — одно окно за раз над HUD, исключены из захвата вместе с ним (`ContentProtected`); Esc или потеря полученного фокуса закрывают. Другие окна закрываются до старта записи.
- Микрофоны для окна звука HUD перечисляет фоновый поток (`microphones.rs`, начинает при запуске); список источников для выбора — поток миниатюр (`hud/picker.rs`). Всплывающие окна, отсчёт и выделение области открываются скрытыми и показываются после первой картинки, редактор, таймлайн и настройки — тоже (`borderless::show_when_drawn`, иначе winit мелькает окном).
- Загрузка модели (`downloads.rs`) — одна на модель на всю программу (`Shared::downloads`), все ждущие окна ждут её; закрытие последнего ждущего отменяет. Экспорт: одна очередь `exports.rs`, задание CLI; диалог `editor/export/` открывается с последним выбором (`settings.json` `export`), кодек — `Exports::encoder` (раз за запуск, своим потоком).
- Запись (`session.rs`, `recorder.rs`): покой → отсчёт → `Launch` (окна закрываются за кадр до старта) → старт → запись → подготовка/отмена → покой. `ProjectRecording` живёт на потоке `devcast-recorder`; UI только шлёт `Request` и берёт `Event`, сам не ждёт. После стопа поток ставит автозумы тем же путём, что `devcast record` (`dc_ops::autozoom::after_recording`), их ошибка — тост. Таймер — часы рекордера минус паузы. «Отменить запись?» ставит паузу. Выход (`on_exit`) останавливает и сохраняет запись. Стоп трогает только запись и отсчёт; стоп во время старта запоминается и уходит после `Event::Started`. `devcast record|app|export` — `remote.rs`: те же пути, ответ ждёт события (`Waiters`), отмена без вопроса; `app quit` отвечает из `on_exit`.
- Трей (`tray.rs`) и хоткеи (`hotkeys.rs`) — в `App`, главный поток, применяются только при изменении; незарегистрированные — `Shared::taken_hotkeys`. Обновления — `updates.rs` (8.2): потоки `dc_update::Updater`, поповер `Kind::Update` только при свободном HUD, установка в `on_exit`, `Request::Update`.
- После стопа (`Event::Stopped`) открывается редактор, HUD прячется; закрытие редактора показывает HUD. Ошибка подготовки — поповер `Kind::Failed`.
- Редактор (`editor/`, docs/design/editor.html): `editor_ui` — вся раскладка, возвращает `Outcome`. Проект — `Document` (`document.rs`): редактор — единственный писатель (lock), меняет проект только `dc_ops::apply` с `Registry::devcast()` — тот же проект, что у `devcast`. Библиотека (`library/`) — проекты папки записей теми же путями `dc_ops`/`dc_project`, что `clip add`, `new`, `new --each`, `ls projects`, `trash`.
- Кнопки и клавиши только ставят `Action` (`actions.rs`); кадр выполняет их после раскладки и перестраивает дорожки (`Tracks::of` по `TimeMap`). Жест — одна команда реестра и один шаг истории; отказ команды — тост, проект не меняется.
- Сохранение: правки несохранённы до Ctrl+S; `session.json` пишет `Autosave` из кадра, события истории идут в `history.jsonl` перед ним. Закрытие окна, «Новый проект» и другой проект при несохранённом спрашивают «Сохранить / Не сохранять / Отмена» (`closing.rs`, `Leave`); «Не сохранять» и «Отбросить» — `Document::discard` (история обнуляется). Проект с `session.json` при открытии спрашивает «Восстановить / Отбросить» (`recovery.rs`).
- Проекты (`projects.rs`, `switch.rs`): последние 16 — `settings.json` `recent_projects`; смена проекта в том же окне — `Shared::open_project` (старый редактор дописывает сессию и уходит первым). Потоки редактора ждутся при drop (`threads::Joined`, последним полем): иначе Windows не переименует папку. Переименование — `ProjectDir::rename` и открытие заново, пока идёт экспорт — отказ. «Сохранить как…» копирует папку на своём потоке. Запросы `devcast` о проекте целиком (`editor/live.rs`: `discard`, `close`, копия `save --as`, `rename`) идут теми же путями, что кнопки.
- «Нейронка» (`editor/ai.rs`, `inspector/ai.rs`): нейронка `dc-agent` в папке проекта, её `devcast` идут вживую (7.32) одним шагом (`Document::top_group` — «Отменить всё»); выбор — `settings.json` `ai` (`Ai::edits` → `Edit::Ai`).
- Устройство редактора по частям (`View`, окно таймлайна, таймлайн, инспектор, превью и правка на нём, воспроизведение, клавиши) — docs/editor-internals.md. Главное: неподвижная мышь ничего не просит; превью рисует тот же путь, что `devcast frame`, берётся новейший запрос; правка на превью — черновик `Document::draft`, отпускание — одна команда; часы воспроизведения — сыгранное устройством звука; клавиши — только таблица `keymap.rs` (id и умолчания — `dc_settings::keymap`, названия — `Title`).

## Как тестировать

- `cargo nextest run -p dc-app`: логика окон и снимки egui_kittest (`tests/snapshots`, тесты — `*_tests.rs`). Редактор — `editor/tests.rs` (проект `editor/test_project.rs`); правка = проект `devcast` тех же команд (`editing_tests::by_cli`), undo с выросшими id — `editing_tests::undone`; сквозные сценарии на фикстуре — `e2e_tests.rs` (`Twin`).
- Превью на WARP = кадр `devcast frame` побайтно (`preview/worker_tests.rs`); распознавание — поддельные процессы (`recognition/job_tests.rs`); замер превью — `preview/speed_tests.rs` (ignored).
- Живой прогон: команды `devcast` и снимки экрана, клики — владелец. Из Claude desktop (MSIX) — `explorer.exe <exe>`.

## Куда не лезть

- Захват и запись — dc-capture, файлы проекта — dc-project, виджеты, тема и все строки интерфейса — dc-ui-kit; поведение эффектов — `fx/*` за швами, регистрация — `editor/lanes.rs`, `inspector/`.
