# dc-core (`crates/core`)

Базовые типы ядра: время, id, геометрия, цвет видео (`VideoColor`), проект, карта времени, команды, история, эффекты.

## Инварианты

- Без IO, GPU и платформенного кода. Ни от кого в workspace не зависит.
- `SourceTime` и `OutputTime` — разные типы (маркер `Timeline`), смешать нельзя. Целые микросекунды; арифметика насыщающая.
- Эффекты привязаны к `SourceTime` записи: `Media.path` + время, а не id клипа (клипы, разрезанные из одной записи, делят её эффекты). Нарезка, порядок клипов и скорость меняют только `Clip.trim/cuts/speeds`; перевод времени — только через `TimeMap` (сегмент `segment_at(t)` знает свой клип и запись `media`; `locate(media, t)` — где играет момент записи).
- `Rect` хранится как `{x, y, w, h}`, читается ещё из текста `x,y,w,h` (так его пишут в CLI). `Media.size` — размер кадра исходника в пикселях, не нулевой. `Clip.crop` — кроп клипа в долях исходника (внутри кадра, стороны ≥ `CROP_MIN`); копия клипа его сохраняет. `Clip.audio` (`ClipAudio`) — звук клипа: mute целиком и свои уровни дорожек (`ChannelLevels`, параметр `None` — от умолчаний `fx/audio-tracks`; громкость 0–100 %, усиление 1–10 проверяет `problems()`); тоже копируется в обе половины. Точка исходника в долях кадра клипа — `crop.to_local(p)`.
- Id: `Id<K: IdKind>`, вид `<префикс><число>`; `IdCounter` никогда не выдаёт номер повторно. Префикс `c` занят клипами.
- Проект меняется **только командами** через `History::apply` / `apply_batch`:
  - пачка применяется по принципу «всё или ничего»;
  - после каждой команды проверяется `Project::problems()`, нарушение = откат и ошибка;
  - undo/redo — снимки изменённых частей (клипы и/или отдельный эффект), обратных команд писать не нужно;
  - команда возвращает `Diff` (`Diff::added/removed/changed(id)`, `Diff::note`); изменила проект с пустым `Diff` = откат и ошибка.
- `IdKind` задаёт `NOUN` (род. п.), `PLURAL` (им. п. мн. ч.) и `LIST` (имя списка `devcast ls <LIST>`). Объекты дорожки эффекта для `ls` — `Effect::LISTS` + `Effect::items` (`Item::of`; объект, который не JSON-объект, — ошибка), место объекта — `Place`: запись и source time (`Item::of`, выход — `TimeMap::output_span`) или сразу время выхода (`Item::on_output`, доп. звук). Ненайденный id — `CommandError::not_found(id, существующие)`.
- Состояние эффекта лежит в `project.effects["<id>"]` как JSON; типизированно — `project.state::<E>()` / `set_state::<E>()`. Состояние, равное `Default`, из проекта удаляется.
- Настройки эффекта (не содержимое) лежат в поле `settings` его состояния (`SETTINGS_FIELD`): только это поле копируют настройки по умолчанию. `EffectInfo::settings` — это поле с заполненными умолчаниями. Команда, меняющая только настройки, объявляет `Op::SETTINGS` (ключ `devcast set`).
- Время в аргументах команд (CLI и планы) — `TimeArg`, `RangeArg`, `RangesArg` (`12.5`, `1:02.5`, `10-12,20-21`); только для ввода, в проекте — микросекунды. Время в аргументах — выходное, команда переводит его через `TimeMap`.
- Телеметрия курсора для эффекта — `cursor::CursorTracks` (по `Media.path`, точки в долях кадра записи; решение 015): данные без IO, читает их верхний слой через `dc-capture`. Так же сочетания клавиш — `keys::KeyTracks` (по `Media.path`, имя `Ctrl+Shift+P` на source time).
- Ответ команды настроек — `diff::Changes` (только изменившиеся поля: `размер 1.00→1.50, тень вкл`). Длина нового объекта по умолчанию — `arg::one_second`.
- Ошибки по-русски и говорят, что делать.

## Как тестировать

- `cargo nextest run -p dc-core`. Общие помощники тестов (клип целой записи) — `src/test_util.rs`. Property-тесты: `time`, `geom` (поворот), `timemap` (непрерывность, монотонность, обратимость). Найденные proptest-случаи хранятся в `proptest-regressions/` — коммитить.
- Допуск `timemap`: на замедлении (скорость < 1) путь выход → исходник → выход может уйти на `ceil(1/скорость)` мкс — это предел разрешения, а не ошибка.

## Куда не лезть

- Сохранение и загрузка папки проекта — `dc-project`. Реестр команд и вывод для CLI — `dc-ops`.
- Конкретные эффекты и их команды — крейты `fx/*`.
