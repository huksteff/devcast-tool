# dc-capture (`crates/capture`)

Запись экрана и звука: модель (источник, настройки, время `HostTime`), платформенный захват (`win/`, позже `mac/`, `linux/`), звук через cpal (`audio/`), папка записи: сегменты fMP4, `manifest.json`, финализация в MP4.

## Инварианты

- Модель (`source`, `config`, `event`) без платформенного кода; платформа только в `win/` и т.п.
- Источник хранится текстом: `screen:<n>` (с 1), `window:<id>` (HWND), `area:x,y,w,h` (пиксели рабочего стола, может быть отрицательным слева от основного монитора). Невозможное значение не создаётся: `Area::new` и разбор текста отказывают.
- `RecordingConfig`: fps только 30/60/120 (`Fps`), неизвестные поля JSON — ошибка; пустое имя микрофона ловит `validate`. Последний выбор — `save`/`load` в файл, путь даёт приложение (решение 008, «Задача 3.8»).
- Windows (`win/`): мониторы и их номера — как в windows-capture (`Monitor::enumerate`, с 1), основной помечен `primary`. Окна — список windows-capture минус окна без заголовка, скрытые DWM (cloaked), рабочий стол и окна своего процесса; порядок — z-order. Превью — один кадр WGC тем же `VideoCapture`, что и запись, уменьшенный на CPU (`BgraImage::preview`).
- Захват WGC (`win::VideoCapture`): курсор выключен всегда; жёлтая рамка выключается, только если API это умеет (`is_border_settings_supported`, Windows 11), иначе пишем с ней (в кадр она не попадает). Область — захват её монитора и кроп на GPU (`CopySubresourceRegion` в свою текстуру, создаётся один раз). Время кадра WGC (`SystemRelativeTime`) — момент показа; в записи кадр ставится в момент прихода: минус опережение, сглаженное `LeadFilter` (решение 007, «Задача 3.9»). Кадры приходят только при изменении картинки (переменная частота). Минимальный интервал WGC — 1 мс (`MIN_UPDATE_INTERVAL`): по умолчанию он ≈ 1/60 с, а кадры идут по тактам основного монитора, и при 144 Гц там запись 60 к/с давала 48.
- Запись видео (`win::VideoRecording`): размер по пробному кадру (вниз до чётного), кодек выбирается до старта (`dc_encode::select`). Кадры ставятся на сетку fps (`FrameGrid`, решение 007): лишние отбрасываются, кадр длится до следующего; если 1 с нет кадров и не пауза, поток кодирования повторяет последний (`REPEAT`, ключевой — сегменты закрываются и на статичном экране). BGRA → NV12 на GPU (D3D11 Video Processor), кадр другого размера — в левый верхний угол без масштаба. Кодирование на своём потоке, очередь 4 кадра.
- Звук (`audio/`, решение 008, «Задача 3.7»): FLAC 48 кГц стерео. `AudioTimeline` ставит пакеты по QPC: дыра > 5 мс — тишина, нахлёст — обрезка, без пакетов дольше 250 мс — тишина до «сейчас − 0,5 с» (`fill_to`: loopback в тишине молчит, а сегменты должны закрываться ради восстановления; часы QPC передаёт `win::Recording`, `audio/` платформы не знает), дрейф часов — PI-петля (`DriftLoop`) на коэффициенте ресэмплера rubato; последние 0,1 с держатся до стопа. Системный звук идёт за устройством по умолчанию (переподключение на `StreamInvalidated`), микрофон — по имени из `list_microphones`, без переподключения. Поток дорожки — свой, открывается до видео. `LevelMeter` — уровень микрофона без записи, 20 раз в секунду.
- `win::Recording` — вся запись: звук открывается первым, все дорожки с тиком 0 в первом кадре видео и концом на стопе (стоп сначала шлётся звуку, потом видео).
- Пауза (решение 007, «Задача 3.13»): `PauseClock` общий для дорожек; всё ставится на шкалу записи (QPC минус паузы) по времени пакета, внутри паузы — отбрасывается. `manifest.pauses` — паузы на QPC. Последний кадр паузы держится и встаёт в слот продолжения. `cancel` удаляет только файлы записи (`remove_recording`) и пустую папку.
- Папка записи (решение 007, «Задача 3.5»): одна `SharedManifest` на все дорожки, сегменты `<дорожка>-NNNNNN.mp4` (`video`, `system`, `mic`) от ключевого пакета, ≥ 2 с, времена внутри от 0; `manifest.json` переписывается атомарно после каждого закрытого сегмента любой дорожки и перечисляет только целые. Финализация: `.tmp` → rename → manifest → удаление сегментов; можно повторять. Удаляются только сегменты дорожек manifest и `*.tmp`, чужие файлы не трогаем.
- Восстановление после вылета (`recover`) — та же финализация по manifest: недописанный сегмент в manifest не попал и удаляется.
- Ввод (решение 009, `input/` — формат и чтение, `win/hooks.rs` — хуки): LL-хук на своём потоке только ставит время QPC и шлёт событие потоку записи. `cursor.bin` — заголовок + записи 24 байта, сброс на диск раз в 100 мс, оборванная запись при чтении отбрасывается; в manifest не входит. Позиции — пиксели картинки от угла источника (`source_origin`; окно — угол на старте, решение 009, «Задача 3.14»). Хуки до видео, события с первого кадра (до него — только позиция), снимаются до времени стопа.
- Телеметрия готовой записи (`input::Telemetry::read`, «Задача 4.16»): события `cursor.bin`/`keys.bin` на source time (время минус `start` видео-дорожки manifest; паузы уже вырезаны), позиции в пикселях как есть; `clicks()` — нажатия с флагом двойного по правилу Windows (500 мс, 4×4 px); `KeyEvent::name()` — `Ctrl+Shift+P`; `cursor_track(dir, media)` — курсор для эффекта (`dc_core::CursorTrack`, решение 015): точки в долях кадра `media.size`, картинки путями проекта рядом с видео, размер PNG — из заголовка; `key_presses()` — сочетания для эффекта клавиш (`dc_core::KeyPress`).
- Курсор (решение 009, «Задача 3.11»): форма — по событиям `OBJID_CURSOR` (`SetWinEventHook`) на том же потоке, тип — сравнение HCURSOR с `IDC_*`, картинка читается в хуке при первой встрече HCURSOR (монохромные — по маскам AND/XOR, +1 px контура), PNG и дедупликацию по пикселям делает поток записи (`cursor-NNNN.png`, id по порядку показа).
- Время — `HostTime`, мкс на общей шкале QPC для видео, звука и ввода.
- Клавиши (решение 009, «Задача 3.12»): фильтр приватности `KeyFilter` вызывается в процедуре `WH_KEYBOARD_LL` до времени и очереди; пишутся только нажатия при Ctrl/Alt/Win и спецклавиши (точный список в решении), Shift сочетанием не считается; AltGr (левый Ctrl со scan 0x21D + правый Alt) и Alt + Numpad — набор текста. Обычный ввод текста не пишется никогда и нигде не хранится. `keys.bin` — записи 12 байт, как `cursor.bin`.
- Проект (решение 007, «Задача 3.14», «Ctrl+C и убитый процесс»): `win::ProjectRecording` создаёт `.dcproj` с `Defaults` на старте, пишет в `media/recording-N/`; клип и при стопе, и при восстановлении добавляет одна `project::add_recording` по собранному manifest (`length`, `size` видео); `unfinished_recordings` + `recover_recordings` — только под lock проекта. Отмена удаляет папку проекта. Дорожки и телеметрия в `Project` не перечисляются: их описывает manifest, папка записи — папка её видео (`project::recording_dir`). `win::on_console_stop` — Ctrl+C/закрытие консоли как стоп.
- unsafe разрешён здесь с комментарием SAFETY. Поэтому здесь же Win32 окна HUD приложения (`win::hud_window`): исключение из захвата (`WDA_EXCLUDEFROMCAPTURE`), скругление регионом окна (`SetWindowRgn`, одинаково на Windows 10 и 11), место окна в физических пикселях.

## Как тестировать

- `cargo nextest run -p dc-capture`.
- Живые тесты `tests/live.rs` с `#[ignore]` пишут экран: рисуют тестовую картинку ffplay на мониторе `DEVCAST_TEST_MONITOR` и снимают его. `DEVCAST_TEST_MONITOR=2 cargo nextest run -p dc-capture --run-ignored=all --no-capture`, затем открыть напечатанные PNG и удалить их вместе с записями. `tests/record.rs` пишет файлы и проверяет их ffprobe; `tests/sound.rs` — системный звук с тоном ffplay (ищется по частоте: в системе может играть что-то ещё), микрофон и индикатор (запись комнаты сразу удаляется); `tests/sync.rs` — вспышка своего окна и писк 17 кГц в начале каждой секунды QPC, расхождение не должно уползать (`DEVCAST_SYNC_SECONDS`, ночью 1800); `tests/input.rs` — SendInput только в своё окно на тестовом мониторе (курсор возвращается; не запускать, пока владелец работает); `tests/recover.rs` пишет в дочернем процессе (тот же exe), убивает его и восстанавливает. `tests/pause.rs` — пауза и отмена, `tests/project.rs` — проект из записи, `tests/segments.rs` — запись сегментами и сборка без экрана. Общие помощники — `tests/common` (тестовая картинка, `fresh_dir`, SendInput в `synthetic.rs`). На ПК владельца записывать можно только монитор 2.
- Фикстуры v2 (`fixtures/recordings/`, задача 3.16) пишет `examples/record_fixtures` — своё окно, SendInput и тоны из `tests/common`; что в каждой — README там. Не тест: ночной `--run-ignored=all` их не перезаписывает.
