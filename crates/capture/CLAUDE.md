# dc-capture (`crates/capture`)

Запись экрана и звука: модель (источник, настройки, события, трейт `Recorder`), платформенный захват (`win/`, позже `mac/`, `linux/`), звук через cpal (`audio/`), папка записи: сегменты fMP4, `manifest.json`, финализация в MP4.

## Инварианты

- Модель (`source`, `config`, `event`, `recorder`) без платформенного кода; платформа только в `win/` и т.п.
- Источник хранится текстом: `screen:<n>` (с 1), `window:<id>` (HWND), `area:x,y,w,h` (пиксели рабочего стола, может быть отрицательным слева от основного монитора). Невозможное значение не создаётся: `Area::new` и разбор текста отказывают.
- `RecordingConfig`: fps только 30/60/120 (`Fps`), неизвестные поля JSON — ошибка; пустое имя микрофона ловит `validate`.
- Windows (`win/`): мониторы и их номера — как в windows-capture (`Monitor::enumerate`, с 1), основной помечен `primary`. Окна — список windows-capture минус окна без заголовка, скрытые DWM (cloaked), рабочий стол и окна своего процесса; порядок — z-order. Превью — один кадр WGC тем же `VideoCapture`, что и запись, уменьшенный на CPU (`BgraImage::preview`).
- Захват WGC (`win::VideoCapture`): курсор выключен всегда; жёлтая рамка выключается, только если API это умеет (`is_border_settings_supported`, Windows 11), иначе пишем с ней (в кадр она не попадает). Область — захват её монитора и кроп на GPU (`CopySubresourceRegion` в свою текстуру, создаётся один раз). Время кадра — `SystemRelativeTime` → `HostTime`. Кадры приходят только при изменении картинки (переменная частота).
- Запись видео (`win::VideoRecording`): размер по пробному кадру (вниз до чётного), кодек выбирается до старта (`dc_encode::select`). Кадры ставятся на сетку fps (`FrameGrid`, решение 007): лишние отбрасываются, повторов нет, кадр длится до следующего. BGRA → NV12 на GPU (D3D11 Video Processor), кадр другого размера — в левый верхний угол без масштаба. Кодирование на своём потоке, очередь 4 кадра.
- Звук (`audio/`, решение 008, «Задача 3.7»): FLAC 48 кГц стерео. `AudioTimeline` ставит пакеты по QPC: дыра > 5 мс — тишина, нахлёст — обрезка, дрейф часов — PI-петля (`DriftLoop`) на коэффициенте ресэмплера rubato; последние 0,1 с держатся до стопа. Системный звук идёт за устройством по умолчанию (переподключение на `StreamInvalidated`). Поток дорожки — свой, открывается до видео.
- `win::Recording` — вся запись: звук открывается первым, все дорожки с тиком 0 в первом кадре видео и концом на стопе (стоп сначала шлётся звуку, потом видео).
- Папка записи (решение 007, «Задача 3.5»): одна `SharedManifest` на все дорожки, сегменты `<дорожка>-NNNNNN.mp4` (`video`, `system`) от ключевого пакета, ≥ 2 с, времена внутри от 0; `manifest.json` переписывается атомарно после каждого закрытого сегмента любой дорожки и перечисляет только целые. Финализация: `.tmp` → rename → manifest → удаление сегментов; можно повторять. Удаляются только сегменты дорожек manifest и `*.tmp`, чужие файлы не трогаем.
- Восстановление после вылета (`recover`) — та же финализация по manifest: недописанный сегмент в manifest не попал и удаляется.
- Время — `HostTime`, мкс на общей шкале QPC для видео, звука и ввода.
- Обычный ввод текста не пишется никогда, только сочетания с модификаторами.
- unsafe разрешён здесь с комментарием SAFETY.

## Как тестировать

- `cargo nextest run -p dc-capture`.
- Живые тесты `tests/live.rs` с `#[ignore]` пишут экран: рисуют тестовую картинку ffplay на мониторе `DEVCAST_TEST_MONITOR` и снимают его. `DEVCAST_TEST_MONITOR=2 cargo nextest run -p dc-capture --run-ignored=all --no-capture`, затем открыть напечатанные PNG и удалить их вместе с записями. `tests/record.rs` пишет файлы и проверяет их ffprobe; `tests/sound.rs` — системный звук с тоном ffplay (ищется по частоте: в системе может играть что-то ещё); `tests/recover.rs` пишет в дочернем процессе (тот же exe), убивает его и восстанавливает. На ПК владельца записывать можно только монитор 2.
