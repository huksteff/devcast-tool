# dc-transcribe (`crates/transcribe`)

Модели Whisper (загрузка с проверкой хэша), распознавание со временем слов, разбиение на реплики. Сейчас готова загрузка моделей (4.12); распознавание и реплики — задачи 4.13–4.14.

## Инварианты

- Модели лежат в `models_dir()` = `%APPDATA%\DevCast\models`; источник и SHA-256 — в `Model` (решение 010).
- Файл под настоящим именем всегда проверен: качаем в `<файл>.part`, проверяем SHA-256, переименовываем. `ensure` доверяет готовому файлу и хэш не пересчитывает.
- Обрыв и отмена оставляют `.part`, следующая загрузка докачивает через `Range`. Хэш не совпал — `.part` удаляется, `HashMismatch`.
- Прогресс — колбэк `Progress { done, total }` с байтами всего файла (с учётом докачанного); отмена — `AtomicBool`, проверяется между кусками по 64 КБ.
- HTTP — только ureq (блокирующий, rustls), без async.
- Результат распознавания кэшируется в cache/ проекта.
- Ошибки по-русски и говорят, что делать.

## Как тестировать

- `cargo nextest run -p dc-transcribe` — без сети: `test_server.rs` (локальный TcpListener с Range) проверяет загрузку, докачку после обрыва, отмену, неверный хэш, чужой `.part`.
- Хэши настоящих моделей из `.deps/models`: `cargo nextest run -p dc-transcribe --cargo-profile release --run-ignored only`.
- Большие загрузки из сети в тестах не делать.

## Куда не лезть

- Папка настроек — `dc_project::settings::dir()`; здесь только подпапка `models`.
- Выбор модели «Точная»/«Быстрая» и строки интерфейса — настройки и `dc-ui-kit`.
