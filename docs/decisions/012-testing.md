# 012. Автотесты интерфейса и рендера, живое управление приложением (проба 1.12)

Дата: 2026-10-28. Код: `spikes/kittest`, `spikes/render`, `spikes/ipc`.

## egui_kittest 0.37 (снимки интерфейса)

- Тест строит панель (заголовок, флажок, слайдер, кнопка, всё на русском).
  - Флажок и кнопка нажимаются через AccessKit по подписи (`get_by_label(...).click()`), состояние проверяется (`record == true`, `clicks == 1`).
  - Снимок PNG рендерится через wgpu. kittest выбирает CPU-адаптер, то есть WARP, как в CI на Windows.
- **10 из 10 повторных сравнений со снимком прошли**, каждое примерно за 0,4 с.
- **Полезная находка:** kittest падает, если в шрифте нет нужного символа («No glyph for "Н"»). Тесты сами ловят квадратики вместо букв. Встроенные шрифты egui (`default_fonts`) кириллицу содержат.
- Снимки лежат рядом с тестом: `tests/snapshots/<имя>.png`, обновляются через `UPDATE_SNAPSHOTS=1`.

## Эталонные кадры рендера (wgpu, свои шейдеры)

| Адаптер | 1080p | 4K |
|---|---|---|
| RTX 3060 Ti, 2 прогона | хэши совпадают | хэши совпадают |
| WARP, 2 прогона | хэши совпадают | хэши совпадают |
| RTX против WARP | отличаются (ожидаемо) | отличаются |

**Решение:**
- эталоны хранятся отдельно для каждого бэкенда (`fixtures/golden/<backend>/…`); CI на Windows сверяет с WARP;
- при сравнении на другом адаптере используется порог (dify / FLIP), а не точное совпадение.
- **5.11:** выбран nv-flip (ꟻLIP, тем же сверяет кадры сам wgpu; без `image`, карта разницы в цветах magma). Адаптер эталонов записан в `fixtures/golden/<backend>/adapter.txt`: на нём — до байта, на другом — ꟻLIP: среднее ≤ 0,02, 99 % пикселей ≤ 0,1. Замер RTX 3060 Ti против WARP на 7 эталонах рендера: среднее 0,0014–0,0064, 99 % — 0,015–0,038. Обновление: `cargo xtask golden update "<почему>"` (`UPDATE_GOLDEN=1`).
- **Этап 5, уборка:** в `adapter.txt` кроме адаптера записан процессор (`имя | драйвер | инфо драйвера | CPU`): WARP компилирует шейдеры под набор инструкций процессора, и одна сборка WARP 10.0.19041.5794 на другом CPU дала пиксели blur, glow и спрайтов с разницей 1–5 уровней (ꟻLIP 0,0000). До байта — только тот же адаптер и тот же CPU, иначе ꟻLIP. Эталоны, сделанные до этого, записаны с CPU `unknown` (на сделавшем их ПК он не записан) и везде сверяются по ꟻLIP до следующего `golden update`.

## egui_inspection + egui_mcp (агент управляет живым окном)

- Приложение собирается с фичей eframe `inspection` (и `accesskit`) и запускается с `EGUI_INSPECTION=1`: открывается порт `127.0.0.1:5719`. Без переменной инспекция полностью выключена, в релизе безопасно.
- `egui-mcp` (crates.io `egui_mcp` 0.3, ставится через `cargo install egui_mcp --locked`) — MCP-сервер. Проверено вручную по протоколу MCP через stdio:
  - `attach` подключился: `{"label":"spike-ipc","transport":"127.0.0.1:5719"}`;
  - `widget_tree` вернул дерево AccessKit с меткой «Значение из CLI: 70»;
  - `screenshot` вернул PNG 420×120, на картинке правильный текст.
- Инструменты: `attach`, `status`, `widget_tree`, `get_widget`, `click`, `drag`, `hover`, `press_key`, ввод текста, `scroll`, `resize`, `screenshot`, `batch`.
- Первая попытка оборвала соединение: на порту оказалось два экземпляра приложения сразу. В продукте при запуске с инспекцией проверяем, что порт свободен, и выводим понятную ошибку.

## Решение

- **Интерфейс:** тесты egui_kittest со снимками и действиями через AccessKit. Все интерактивные элементы обязаны иметь доступное имя: kittest 0.37 это проверяет.
- **Визуальная проверка агентом** (PROCESS.md): в задаче 6.1 egui-mcp подключается к Claude Code как MCP-сервер проекта (`.mcp.json`). Приложение в dev-сборке собирается с `inspection`.
- **Не проверено:** снимки и эталоны в GitHub Actions на `windows-latest` (WARP). Нужен push ветки, и это входит в задачу 0.5.
