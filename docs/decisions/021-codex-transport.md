# 021. Только команды DevCast в Codex

Дата: 2026-11-12. Задача 8.12. Требование владельца: тот же принцип, что у Claude Code — разрешён только devcast, без MCP. Заменяет прежние варианты через MCP и общий approve-for-me.

## Почему изменён запуск

У codex exec нет аналога Claude --allowedTools. prefix_rule разрешает или запрещает отдельные префиксы при выходе из песочницы, но не является полным белым списком команд внутри неё. Общий автоматический проверяющий также не гарантирует запрет всех прочих программ.

## Решение

Используется штатный Codex app-server через stdio и его клиентские dynamicTools. Это нативный протокол Codex, не MCP-сервер DevCast. Подписка, поиск CLI, вход, выбор модели и интерфейс остаются прежними. Claude Code продолжает свой прежний запуск с Bash(devcast *) и PowerShell(devcast *).

Клиент регистрирует один инструмент devcast с единственным полем args — массивом строк без имени программы. Путь установленного devcast.exe, cwd проекта и DEVCAST_GROUP фиксирует клиент, включая продолжение разговора. Модель не может передать другое имя EXE, окружение или рабочую папку. Неизвестные поля и чужие инструменты отвергаются. Аргументы передаются как argv: символы оболочки в тексте остаются текстом, оболочка не запускается.

Для потока модели запрещены общая оболочка, сторонние инструменты, просмотр изображений, браузер, генерация, подагенты, пользовательские хуки и плагины. Права потока — read-only, approvalPolicy=never, без сред выполнения. До первого turn/start клиент проверяет эффективные флаги, отключает каждую найденную MCP-запись на время потока и проверяет инвентарь: только disabled с пустыми tools. Неприменённые ограничения и неизвестный инвентарь завершают запуск до обращения к модели. Любые запросы разрешений или неизвестные серверные RPC отклоняются.

Только клиент, после проверки запроса инструмента, формирует command/exec для фиксированного devcast.exe. Обычный токен пользователя нужен именно этому разрешённому процессу для существующего Windows pipe редактора. sandboxPolicy=dangerFullAccess относится только к сформированному клиентом вызову EXE; поток модели остаётся read-only и не получает API запуска произвольных команд. Другого пути правки проекта нет: CLI использует прежние bounds::check, реестр, IPC и историю.

Первый запрос — thread/start, продолжение — thread/resume; dynamicTools сохраняются в метаданных разговора самим Codex. Каждое продолжение получает новую группу отмены. При переходе со старого exec-запуска нужен новый разговор. Код пользователя и настройки Codex на диске не меняются.

## Ход работы и остановка

Нативные события становятся общими Event dc-agent. Команду и результат клиент показывает ровно один раз; токены считаются для текущего запуска. Все процессы команд — потомки app-server, остановка гасит дерево. Сигнал остановки проверяется до отправки command/exec; закрытый поток без результата — ошибка с диагностикой stderr.

## Проверка

Регрессия сначала воспроизведена на старом запуске: ожидался app-server с отключённой оболочкой, получен exec. Тесты проверяют подмену EXE, cwd и окружения, попытку запуска другой программы, запрос разрешений, shell-синтаксис внутри буквального аргумента, чужой ход работы, вызов до проверки политики и отмену до отправки команды. Поддельный двусторонний app-server проверяет первый запуск, resume, команды, расход и конечный ответ. CLI проверяет общий IPC и отдельные группы undo/redo.

Конфигурация проверена с установленным Codex CLI 0.166.0-alpha.5.1 без запроса к модели: readOnly, never, отключённая оболочка и сторонние функции, MCP-запись disabled с нулём инструментов. Живой монтаж настоящей моделью новой версии ещё нужен; задача 8.12 и ai.codex остаются открытыми до полной приёмки.

Проверки 12.11.2026: `cargo xtask verify` полностью зелёный, включая Clippy всего workspace и тесты трёх затронутых крейтов (dc-agent, dc-cli, dc-app). Настоящий app-server выполнил разрешённый `devcast help` на фикстуре с кодом 0; модель при этой проверке не запускалась.
