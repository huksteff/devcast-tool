# 009. Хуки мыши и клавиатуры, картинки курсора (проба 1.9)

Дата: 2026-10-28. Код пробы: `spikes/hooks`. Windows 11 26100. Синтетический ввод шёл только в собственное тестовое окно пробы на левом мониторе.

## Хуки

`WH_MOUSE_LL` и `WH_KEYBOARD_LL` ставятся из потока с циклом `GetMessageW`. Время каждого события — QPC в момент вызова хука, на той же шкале, что кадры WGC и звук cpal (решения 007, 008).

| Проверка | Результат |
|---|---|
| 50 быстрых кликов поштучно (нажатие 10 мс, пауза 20 мс; ~33 клика/с, быстрее человека), 3 прогона | 50/50 нажатий и 50/50 отпусканий каждый раз |
| 100 событий одной пачкой `SendInput` (нереалистично) | теряется 2–3 события из 100 |
| Клавиши: a, b, c, Shift+D, Ctrl+Shift+P, F5, Esc | сохранены только `Ctrl+Shift+P`, `F5`, `Esc`; 4 обычных нажатия отброшены и нигде не хранятся |

- **Правило приватности:**
  - сохраняется только нажатие при зажатом Ctrl, Alt или Win, либо спецклавиша (Esc, Enter, Tab, Backspace, Delete, стрелки, F1–F24);
  - Shift сам по себе сочетанием не считается (Shift+буква — это набор текста);
  - состояние модификаторов хук ведёт сам по событиям нажатия и отпускания: в LL-хуке `GetKeyState` ещё не обновлён.
- **Не проверено:** события над окнами, запущенными с правами администратора. Без UAC такое окно в пробе не создать. Ожидается, что окна с повышенными правами хук обычного процесса не видит; проверить в 3.10 вручную вместе с владельцем.

## Картинки курсора

`GetIconInfo` (горячая точка) → `DrawIconEx` в 32-битную DIB 64×64 → RGBA → PNG. Тип курсора определяется сравнением `HCURSOR` с общими системными курсорами (`LoadCursorW(None, IDC_*)`): стрелка, I-beam, рука, 4 ресайза, перемещение, «нельзя», ожидание, фоновое ожидание. Текущий курсор (`GetCursorInfo`) распознан как `arrow`.

- Цветные курсоры (стрелка, рука, ресайзы и др.) получаются правильно: белые с чёрным контуром и прозрачным фоном, горячие точки верные (стрелка (0,0), рука (6,0)).
- **Монохромные курсоры** (I-beam, у него нет цветной битмапы, есть маски AND/XOR) через `DrawIconEx` дают 0 видимых пикселей. В 3.11 их обрабатываем отдельно, по маскам:

  | AND | XOR | Пиксель |
  |---|---|---|
  | 0 | 0 | чёрный |
  | 0 | 1 | белый |
  | 1 | 0 | прозрачный |
  | 1 | 1 | «инверсия» — рисуем чёрным с белым контуром в 1 px |

  Так же поступают OBS и Cap.

## Решение

- Хуки ставятся на отдельном потоке с собственным циклом сообщений. Обработчик только записывает событие с QPC в очередь и сразу возвращает управление: Windows снимает хук, который отвечает дольше `LowLevelHooksTimeout`.
- Фильтр приватности — в самом хуке, до записи куда-либо. На него нужен юнит-тест (задача 3.12).
- Картинки курсора кэшируются по `HCURSOR`, монохромные конвертируются по маскам.

## Задача 3.10: мышь и `cursor.bin`

- Хук `WH_MOUSE_LL` на потоке `devcast-input-hooks` с циклом `GetMessageW`; событие получает время QPC в хуке и уходит по каналу в поток записи `devcast-input-writer`. Хуки ставятся до видео, запись событий — с первого кадра видео (как у звука); до него помнится только позиция, и файл начинается с неё в момент старта. Хуки снимаются до того, как берётся время стопа, поэтому все события раньше стопа.
- Координаты — физические пиксели рабочего стола (`MSLLHOOKSTRUCT.pt`, начальная — `GetPhysicalCursorPos`), слева от основного монитора отрицательные. Перевод в координаты источника — при сборке проекта (3.14). Движение без смены позиции не пишется.
- **Формат `cursor.bin`** (код: `crates/capture/src/input/cursor.rs`, `input/file.rs`). Заголовок 8 байт: `DCCU`, версия u16 (1), размер записи u16 (24). Дальше записи по 24 байта, little-endian:

  | Байты | Поле |
  |---|---|
  | 0..8 | время, i64 мкс QPC (тик 0 записи — `start` дорожки в manifest) |
  | 8 | тип: 0 движение, 1 кнопка нажата, 2 отпущена, 3 колесо, 4 горизонтальное колесо |
  | 9 | кнопка: 1 левая, 2 правая, 3 средняя, 4 X1, 5 X2; иначе 0 |
  | 10..12 | 0 |
  | 12..20 | x, y: i32 |
  | 20..24 | i32: шаг колеса (120 на щелчок, + от себя / вправо), иначе 0 |

  Неизвестный тип или кнопка, чужая сигнатура, более новая версия — ошибка чтения (`read_cursor`).
- **Вылет:** файл дописывается потоком и сбрасывается на диск не реже раза в 100 мс. При вылете процесса теряется не больше 100 мс событий; оборванная последняя запись при чтении отбрасывается. Файл в manifest не входит: `recover` и финализация его не трогают, видео при вылете теряет больше (недописанный сегмент).
- **Замер** (Windows 10 19045, своё окно на мониторе 2, SendInput; до запрета живых тестов, 4 прогона): 50 движений, 50 левых кликов (10 мс нажатие, 20 мс пауза), правый, средний, 3 щелчка колеса, 2 горизонтального — получены все: 52 нажатия, 52 отпускания, 5 колёс, все 50 точек движения. Задержка от вызова SendInput до времени в хуке: медиана 186–204 мкс, минимум 120–131 мкс, максимум 2,5–18 мс. Владелец в это время двигал свою мышь: она сдвигала клики до ~25 px, лишние движения тоже записаны (так и должно быть).
