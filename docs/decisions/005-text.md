# 005. Текст в кадре (проба 1.5)

Дата: 2026-10-28. Код пробы: `spikes/text`. glyphon 0.12 + cosmic-text 0.19 на wgpu 30, рендер без окна в PNG 1600×900.

## Шрифты

Встроенные шрифты из решения 000 скачаны из официального репозитория Google Fonts (`github.com/google/fonts`, лицензия OFL):
- Inter (переменный);
- Montserrat (переменный);
- Roboto (переменный);
- PT Serif Regular;
- JetBrains Mono (переменный).

В продукте они лежат в `assets/fonts/` вместе с файлами лицензий OFL (задача 6.2).

## Результат (проверено глазами по кадру)

- **Кириллица** во всех пяти шрифтах: панграммы с «ё», «щ», «ъ» без пропусков и квадратиков.
- **Цветные эмодзи** 🎬 🎮 ✅ 🔥 👍 через шрифт Segoe UI Emoji; символы ● ▶ ■ ⏸ подхватываются из запасных шрифтов. Именно «●» не было во встроенном шрифте egui (решение 001).
- **Масштаб ×3** даёт чёткие буквы обоими способами: через размер в `Metrics` и через `TextArea.scale`. Глифы растеризуются под итоговый размер, мыла нет.
- **Мелкий текст 12 px** читается.
- **Шрифт из файла** (`load_font_file`) работает — так подключаются свои .ttf/.otf из `assets/` проекта.
- **Скорость:** загрузка шрифтов около 11 мс, подготовка 10 строк (шейпинг и растеризация) около 8–10 мс в первый раз, дальше глифы берутся из атласа.

## Решение

- Текст в кадре (аннотации, субтитры, облачко, показ клавиш) рисуется через glyphon в том же wgpu-рендере.
- **Набор шрифтов должен быть одинаковым на всех ПК**, иначе кадры экспорта разные. `FontSystem::new_with_fonts([])` всё равно подгружает системные шрифты (в пробе 174 начертания). В продукте создаём `FontSystem` с пустой базой (`new_with_locale_and_db` + пустой `fontdb::Database`) и загружаем только:
  - встроенные шрифты из `assets/fonts/`;
  - шрифт эмодзи и символов — Noto Color Emoji (OFL, кладётся в `assets/fonts/`) вместо системного Segoe UI Emoji;
  - шрифты из `assets/` проекта.
- Значки интерфейса (REC, пауза, стоп) рисуются фигурами или берутся из того же набора шрифтов, а не из системы.
- Эталонные кадры с текстом стабильны, потому что шрифты свои.

## Уточнение в 5.6

- **Noto Color Emoji — сборка CBDT** (цветные PNG-картинки) из релиза `googlefonts/noto-emoji` v2.051 (`fonts/NotoColorEmoji.ttf`, OFL). В `google/fonts` лежит только сборка COLRv1 (+SVG): swash, растеризатор glyphon, её не рисует, эмодзи выходили пустыми. CBDT swash масштабирует под размер; 128 px выглядит чётко.
- **Откуда файлы:** `cargo xtask deps` скачивает их в `.deps/fonts/` (google/fonts на закреплённом коммите, noto-emoji по тегу) и сверяет SHA-256; git-хэши файлов при составлении списка сверены с репозиториями. Лицензии OFL лежат рядом (`<семейство>-OFL.txt`). В продукте те же файлы копируются в `assets/fonts/` (6.2).
- **Рендер грузит шрифты только из папок, которые ему дали** (`Compositor::load_fonts`: встроенные и `assets/` проекта), база шрифтов изначально пустая. Нет шрифта у текста — ошибка `NoFont`, а не подмена системным.
- **Начертания:** жирный и курсив — настоящие (переменная ось `wght` и отдельные italic-файлы; у PT Serif — четыре файла). Подчёркивание — по метрикам шрифта (смещение и толщина), рисуется фигурой поверх букв, по куску на каждый цвет текста.
- **Раскладка как в экспорте v1:** перенос по ширине бокса минус отступы (длинное слово переносится по буквам), блок строк по центру бокса по вертикали, бокс обрезает текст, плашка на каждую строку по её буквам без хвостовых пробелов.
- **Поворота текста нет:** glyphon рисует буквы без поворота. Повёрнутый текст (5.29) — через отрисовку в текстуру и спрайт (5.7).
- **Замер** (RTX 4060, кадр 1080p с 13 строками текста разных шрифтов, плашками и эмодзи, ожидание GPU каждый кадр): загрузка шрифтов 1 мс; первый кадр (шейпинг и растеризация) 77 мс; следующие 1,5 мс в 1080p и 1,8 мс в 4K (шейпинг каждый кадр заново). WARP: 28 и 93 мс.

## Свои шрифты (решение владельца 2026-11-02)

- Свои .ttf/.otf лежат в `assets/fonts/` проекта. Кладёт их `devcast font add <файл>` или «Добавить шрифт…» редактора (`dc_ops::import_font`): копия под своим именем (`copy_in`), семейство — английское имя из файла. Файл без шрифта и семейство встроенного шрифта — ошибка с подсказкой.
- Добавление файла — не команда реестра: `project.json` не меняется, истории нет. Команда с undo — стиль, который выбирает семейство (`text set --font`, `captions style --font`), как у картинок (копия остаётся, отменяется `image set`).
- Загрузка одна для всех: `dc_ops::fonts::load(root, …)` — встроенные, затем `assets/fonts/` в `TextMeasure` и `Compositor` (экспорт, `frame`/`sheet`, превью). Повторная загрузка папки добавляет только новые файлы, поэтому превью подхватывает шрифт со следующей ревизии проекта.
- Неизвестное семейство: команды стиля его принимают (команда — чистая функция проекта, файлов не видит), кадр и экспорт отказывают `NoFont` с подсказкой `devcast font add`. Так уже было у текста; `captions style` раньше пускал только встроенные и теперь работает так же.
