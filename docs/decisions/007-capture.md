# 007. Захват экрана (проба 1.7)

Дата: 2026-10-28. Код пробы: `spikes/capture`. windows-capture 2.0.1 (WGC), Windows 11 26100, RTX 3060 Ti, левый монитор DISPLAY7 1920×1080. Проба шла ночью без владельца за компьютером.

## Что работает

- **Захват окна** (`Window::from_name`):
  - видео 60 fps за 4 с — 238 кадров, ровно 60,0 fps, интервалы 7–28 мс;
  - окно WinForms с анимацией 60 с — 2746 кадров (~46 fps, это предел таймера WinForms), без сбоев.
- **Таймстемпы** `SystemRelativeTime` — на шкале QPC и строго монотонные. Отличаются от «сейчас» на −6…−12 мс: это время ближайшего vsync, оно в будущем. Значит, видео, звук и ввод можно сводить по одной шкале QPC (решение для 3.9).
- **Без курсора и без жёлтой рамки** (`CursorCaptureSettings::WithoutCursor`, `DrawBorderSettings::WithoutBorder`): на кадре нет ни курсора, хотя он стоял над окном, ни рамки.
- **Окно, перекрытое другими окнами**, всё равно захватывается целиком.

## Проблема: захват всего монитора почти не присылает кадров — ОТКРЫТО

Захватываем весь левый монитор, а на нём идёт видео 60 fps или меняет цвет окно WinForms. Захват выдаёт 2–9 кадров за 5 с: в начале и в конце. Проверено всё, что можно было проверить без владельца:

| Проверка | Результат |
|---|---|
| Окно видео поверх всех (виден на обычном GDI-скриншоте) | WGC: 2 кадра за 4,8 с |
| Окно WinForms (два GDI-скриншота с разницей 0,5 с подтверждают смену цвета) | WGC: 6–9 кадров за 5,8 с |
| Минимальный интервал обновления: по умолчанию / 1 мс / 16 мс | без разницы |
| DXGI Desktop Duplication на том же мониторе | видео: 2 кадра за 4 с; WinForms: ~3 fps |
| Таймаут выключения экрана 20 мин, простой во время теста ~5 мин, мониторы `Active` | экраны не спали |

Оба системных API (WGC и DXGI) видят рабочий стол левого монитора почти неподвижным, хотя GDI-скриншот показывает изменения. Захват окна при этом работает. Гипотезы, по убыванию вероятности:
1. Особенность сессии без пользователя: простой, энергосбережение, режим композиции DWM.
2. Аппаратные слои (MPO), которые обходят композицию DWM.
3. Особенность конкретного монитора или драйвера.

**Что нужно:**
- повторить с владельцем за компьютером: двигать окна, печатать, прокручивать браузер на левом мониторе и смотреть число кадров;
- сравнить с захватом основного монитора;
- проверить OBS (захват экрана) на том же мониторе.

Без этого задачу 3.3 (запись экрана) не начинать. Вопрос вынесен в `docs/QUESTIONS.md`.

## Чего не проверили

- Область через кроп на GPU: в пробе проверен только CPU-кроп `buffer_crop`, и из-за проблемы выше кадров было мало. GPU-кроп (`CopySubresourceRegion` из `as_raw_texture`) — в задаче 3.3.
- 10 минут непрерывной записи: проверена минута захвата окна. Длинный тест — в 3.9 (30 минут, ночной).

## Решение

- Захват — windows-capture 2 (WGC). Курсор и рамка выключены; PTS — `SystemRelativeTime` на шкале QPC.
- Частота кадров переменная: кадр приходит только при изменении. Энкодер записи (3.4) должен принимать переменную частоту или повторять последний кадр по таймеру. Это решается в 3.4 вместе с проблемой выше.
- Окно HUD исключено из захвата через `WDA_EXCLUDEFROMCAPTURE` (решение 001). Это действует и на WGC.
