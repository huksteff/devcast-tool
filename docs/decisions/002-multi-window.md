# 002. Несколько окон (проба 1.2)

Дата: 2026-10-28. Код пробы: `spikes/windows`.
Проверено на Windows 11 26100, NVIDIA RTX 3060 Ti. Окна стояли на мониторе 1920×1080 (масштаб 100%).

## Что проверяли

Главное окно (редактор) и два deferred viewport eframe 0.37: отдельный таймлайн и HUD без рамки поверх всех. Каждое окно просит перерисовку раз в 33 мс. Мерили кадры каждого окна за 7 с и процессорное время за 4 с.

## Результаты

| Режим | Кадры за 7 с (редактор / таймлайн / HUD) | CPU |
|---|---|---|
| Анимация, release | 203 / 202 / 204 (~29 fps каждое) | 11% одного ядра |
| Анимация, debug | 186 / 185 / 186 | 36% одного ядра |
| Простой (перерисовки не запрашиваются), release | 6 / 4 / 5 | 0% |

- Второстепенные окна не отстают от главного и не замирают.
- В простое процессор не тратится: eframe перерисовывает только по запросу.
- `pixels_per_point` у всех окон 1.0.

## Чего не проверили

- **Баг egui #8466** (второе окно замирает, когда фокус в главном). Чтобы воспроизвести честно, главное окно нужно сделать активным, а это забирает фокус у пользователя. Проверяем в задаче 7.26: живой прогон отдельного таймлайна при активном редакторе.
- **Смешанный DPI** — на этой машине оба монитора со 100%. Проверка переносится в 8.7 (ручной прогон на втором ПК) или к задаче 6.7, если найдётся монитор с другим масштабом.

## Решение

- Окна делаем через deferred viewports eframe: отдельный таймлайн, HUD, выпадающие панели HUD и оверлей выбора области.
- Каждое окно перерисовывается только по запросу. Во время воспроизведения — `request_repaint_after(шаг кадра)`. Безусловный `request_repaint()` запрещён.
- Производительность меряем только на release-сборке: debug в 3 раза медленнее и вводит в заблуждение.
