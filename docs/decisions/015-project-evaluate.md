# 015. Где живёт `evaluate` проекта

Дата: 2026-10-29. Код: `crates/ops/src/evaluate.rs`, вклады эффектов — `fx/*/src/evaluate.rs` (и `fx/crop/src/canvas.rs`).

## Задача

Решение 4 ARCHITECTURE: `evaluate(project, t) -> Scene` — одна функция для превью, экспорта и `devcast frame`/`sheet`. Решение 5: у каждого эффекта свой `evaluate` в своём крейте. Нужен один вызов, который собирает сцену из всех эффектов в постоянном порядке.

## Ограничения слоёв

- `dc-encode` (экспорт, PNG кадров) и `dc-render` — базовый слой: эффекты им не видны.
- Эффекты зависят только от `dc-core`, `dc-render`, `dc-ui-kit` и друг друга не видят.
- Видят все эффекты только `dc-ops` и верхний слой (`dc-cli`, `dc-app`). Превью живёт в `dc-app`, экспорт и кадры CLI — в `dc-cli`.

## Решение

- `evaluate` проекта — `dc_ops::Evaluator` в слое ops: ниже его нет места, которое видит все эффекты, а `dc-cli` и `dc-app` оба от него зависят. Отдельный крейт ради одного файла не заводим.
- `Evaluator::new(project)` один раз строит `TimeMap`, читает состояния эффектов и размер кадра (`canvas`); `evaluate(t)` — чистая функция без ошибок, её зовут на каждый кадр. Битое состояние эффекта или проект без клипов — ошибка `new`, до первого кадра.
- Эффект отдаёт свою часть функцией в своём крейте (`dc_fx_cut::evaluate`, `dc_fx_crop::canvas`, …). Порядок вызовов — в `Evaluator::evaluate`; порядок рисования задают полосы `Band`, внутри полосы — порядок вызовов.
- Экспорт и `frame_png`/`sheet_png` эффектов не знают: получают готовые `Scene` (`Timeline::scene` — замыкание над `Evaluator`).
- Снимки: у каждого эффекта insta-снимок своего `evaluate` в 10–20 моментах; у `Evaluator` — снимок собранной сцены.

## Отклонено

- Трейт `Evaluate` в `dc-core`: `Scene` лежит в `dc-render`, ядро про неё не знает.
- Реестр функций эффектов (как `EffectInfo`): порядок всё равно постоянный и короткий, явный вызов проще читать и проверять.
