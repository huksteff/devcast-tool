# Аннотации: выжимка из v1 (задача 0.12)

Агент, который делает аннотации в v2, читает только этот файл. Код v1 открывать не нужно. Все ссылки `файл:строка` даны относительно `.v1/src/`. Метка **«не переносить»** означает баг или костыль v1, который повторять нельзя.

## 0. Обозначения

- `t` — время в мс. В v1 это время монтажного таймлайна (output time): превью берёт `Math.round(timelineTime*1000)` (`components/video-editor/VideoPlayback.tsx:2913`), экспорт — время таймлайна в мс без округления (`lib/exporter/modernFrameRenderer.ts:2988-2990`).
- `smooth(p) = p*p*(3 - 2*p)` (smoothstep), `clamp01(x) = min(1, max(0, x))`.
- `R = (Rx, Ry, Rw, Rh)` — прямоугольник видимого видео после кропа в пикселях кадра (`maskRect`, `lib/exporter/modernFrameRenderer.ts:3125-3131`). В v1 вокруг него мог быть фон, в v2 фона нет, поэтому `R` = кадр проекта.
- **ref-px** — пиксель при ширине `R`, равной 1920. Почти все «пиксельные» параметры аннотаций хранятся в ref-px.
- `cam = (s, tx, ty)` — камера зума, `screen = scene*s + (tx, ty)`.
- `k = max(0.01, Rw/1920) * cam.s` — сколько пикселей кадра в одном ref-px (`lib/exporter/annotationRenderer.ts:18-20, 640-642, 661`).
- В v1 было **три** рендера аннотаций: превью на DOM/SVG (`components/video-editor/AnnotationOverlay.tsx`), экспорт на Canvas2D (`lib/exporter/annotationRenderer.ts`) и экспорт Pixi-спрайтами (`lib/exporter/modernFrameRenderer.ts:1557-1640`). Эталоном считается Canvas2D-экспорт. Расхождения превью с ним отмечены отдельно.

## 1. Объём

Переносятся типы `text`, `image`, `figure` (arrow, rectangle, ellipse, circle, line, highlight), `drawing` и `blur` (`types.ts:457`).

Не переносятся:
- тип `click` — его заменяет эффект клика;
- тип `cursor-callout` — это облачко курсора, задача 0.11;
- переходы `bounce`, `zoom`, `swing` (`types.ts:716-748`) и `draw-out` (`types.ts:689-701`), а с ними «ластик в Draw Out» (`showEraserInDrawOut`).

В v1 нет совсем, это новое для v2: поворот аннотации пользователем, направляющие и привязка, draw-in для фигур, стрелка по двум точкам, настройка радиуса плашки текста, свои шрифты файлами и статический (неанимированный) градиент.

## 2. Модель данных

`AnnotationRegion` (`types.ts:922-943`) содержит поля `id`, `startMs`, `endMs`, `type`, `content` (плюс устаревшие `textContent` и `imageContent`), `position{x,y}`, `size{width,height}`, `positionKeyframes[]`, `style`, `zIndex`, `trackIndex`, `figureData`, `drawingData`, `stages`, `blurIntensity`, `blurColor`.

### 2.1. Координаты

`position` задаёт **левый верхний угол** бокса, `size` — его ширину и высоту. Оба значения в процентах от `R` (0..100): x и ширина — от `Rw`, y и высота — от `Rh`. Бокс в пикселях:

```
X = Rx + x/100*Rw;  Y = Ry + y/100*Rh;  W = w/100*Rw;  H = h/100*Rh
X' = X*cam.s + cam.tx;  Y' = Y*cam.s + cam.ty;  W' = W*cam.s;  H' = H*cam.s
```

Источники: `lib/exporter/annotationRenderer.ts:35-49, 651-659`, `AnnotationOverlay.tsx:83-90`.

- По умолчанию `position = (50, 50)` и `size = (30, 20)`: бокс идёт от центра кадра вправо вниз (`types.ts:945-953`).
- Минимальный размер при ресайзе — 1 % (`AnnotationOverlay.tsx:51-57, 128-133`). При загрузке размер зажимается в [1, 10000] (`components/video-editor/projectPersistence.ts:669-683`), позиция не зажимается.
- Точки рисунка хранятся в процентах **от бокса** (0..100), а не от кадра (раздел 7).
- Центр поворота и масштаба анимаций — центр бокса.
- Совет для v2: хранить доли 0..1 от кадра проекта. Это совпадает с v1, потому что `R` в v2 и есть кадр.

### 2.2. Время

- `startMs` и `endMs` — целые мс таймлайна.
- Аннотация активна при `startMs <= t <= endMs`, **обе границы включены** (`components/video-editor/videoPlayback/annotationVisibility.ts:4-14`, `lib/exporter/annotationRenderer.ts:629-631`).
- Новая аннотация ставится в позицию курсора времени, длительность `min(1000, totalMs)`. Если не помещается до конца, сдвигается влево (`timeline/hooks/useTimelineEditorRuntime.ts:260-281`, `timeline/hooks/actions/useTimelineZoomActions.ts:40`).
- Минимальная длина на таймлайне 100 мс (`timeline/core/time.ts:55`). При загрузке проекта `endMs >= startMs + 1` (`projectPersistence.ts:603`).
- Дубликат ставится на ту же дорожку через 100 мс после конца последней её аннотации (`hooks/useAnnotationRegionCommands.ts:178-201`).
- В v2 по ARCHITECTURE всё привязано ко времени исходника. Как переводить, см. вопрос 6.

### 2.3. Слои (подтверждено)

Порядок отрисовки: сортировка по возрастанию `(trackIndex ?? 0)`, затем `zIndex`. Кто рисуется позже, тот сверху (`annotationLayerOrder.ts:3-9`).

- Дорожка 0 — первая под видео. Чем ниже дорожка на таймлайне, тем больше индекс и тем выше слой. Это подтверждают `config/Changelog.md:27` («нижняя дорожка перекрывает верхнюю») и тест `annotationLayerOrder.test.ts:5`.
- `zIndex` — счётчик создания (`useAnnotationRegionCommands.ts:56, 194`), поэтому на одной дорожке новая аннотация лежит выше.
- Аннотации могут перекрываться по времени даже на одной дорожке: проверки нет (`timeline/hooks/useTimelineDndBindings.ts:106`).
- Клик по уже выбранной аннотации выбирает следующую в порядке слоёв (`VideoPlayback.tsx:2922-2936`).
- Порядок относительно других слоёв в экспорте: видео < курсор < аннотации < субтитры (`modernFrameRenderer.ts:543-562, 1537-1552`). В превью DOM-слой аннотаций лежит **над** субтитрами (`VideoPlayback.tsx:2893`), то есть превью и экспорт расходятся (вопрос 10).
- Motion blur зума на аннотации не действует: фильтры висят только на видео (`modernFrameRenderer.ts:489, 545`).
- **Не переносить:** спрайтовый путь экспорта сортирует только по `zIndex` и не смотрит на `trackIndex` (`modernFrameRenderer.ts:1569-1571`).

## 3. Этапы «вход → ожидание → выход» и анимации

Длительности входа и выхода задаются слайдером от 0 до `(длина − другая стадия)` с шагом 10 мс (`AnnotationSettingsPanel.tsx:385-406`). При сохранении значения зажимаются: `in = clamp(round(in), 0, span)`, `out = clamp(round(out), 0, span − in)` (`useAnnotationRegionCommands.ts:206-226`).

Состояние кадра считается одной функцией для превью и экспорта (`types.ts:647-800`):

```
fn stage(a, t) -> {alpha, tx, ty, scale, textP, drawP}:     // по умолчанию 1,0,0,1,1,1
  if a.stages is None: return IDENT
  if in_enabled && t < start + in_ms:
      p = clamp01((t - start) / max(1, in_ms)); tr = in_tr; entering = true
  elif out_enabled && t > end - out_ms:
      p = clamp01((end - t) / max(1, out_ms)); tr = out_tr; entering = false   // p идёт 1 → 0
  else return IDENT
  if tr == none: return IDENT
  e = smooth(p)
  match tr:
    fade:        alpha = p                                   // ЛИНЕЙНО, без smooth (types.ts:791-799)
    pop:         alpha = e; scale = 0.58 + 0.42*e + 0.14*sin(PI*e)
    slide-up:    alpha = e; ty = (1-e) * (entering ? +72 : -72)
    slide-down:  alpha = e; ty = (1-e) * (entering ? -72 : +72)
    slide-left:  alpha = e; tx = (1-e) * (entering ? -96 : +96)
    slide-right: alpha = e; tx = (1-e) * (entering ? +96 : -96)
    typewriter:  textP = p                                   // линейно
    draw-in:     drawP = p                                   // линейно
```

Формулы по строкам `types.ts`: pop — 749-758, slide — 759-790, typewriter — 702-711, draw — 689-701.

- Сдвиг slide задаётся в ref-px: 72 по вертикали и 96 по горизонтали.
- Pop: при `e=0` масштаб 0.58, при `e=0.5` 0.93, максимум ≈1.0013 при `e≈0.904`, при `e=1` ровно 1. То есть это рост с едва заметным перелётом.
- Если вход и выход перекрываются, побеждает вход.

Применение (`lib/exporter/annotationRenderer.ts:649-668`, превью — `AnnotationOverlay.tsx:738, 795`):

```
globalAlpha = stage.alpha            // на всю аннотацию; умножается на opacity фигуры
M = T(cx + tx*k, cy + ty*k) · S(scale) · T(-cx, -cy)      // (cx,cy) — центр бокса после камеры
```

Сдвиг не умножается на `scale`.

Какие переходы предлагает UI v1 (`AnnotationSettingsPanel.tsx:337-361`):
- всем типам — none, fade, pop и slide в 4 стороны;
- тексту — ещё typewriter;
- рисунку — draw-in (на входе).

Draw-in для фигур в v1 **нет**, его нужно спроектировать (вопрос 12).

**Не переносить:**
- При загрузке проекта переходы проходят по белому списку none/fade/pop/slide-up/slide-down. Поэтому slide-left/right, typewriter и draw-in после переоткрытия молча становятся `fade` (`projectPersistence.ts:780-798`).
- Изменение длины аннотации на таймлайне не пересчитывает длительности стадий (`useAnnotationRegionCommands.ts:73-95`).
- Названия непоследовательны. `slide-up` и `slide-down` называют направление движения: up въезжает снизу и уезжает вверх. `slide-left` и `slide-right` называют сторону появления: left въезжает слева и уезжает вправо (тест `annotationModel.test.ts:41-45`). См. вопрос 4.
- Typewriter показывает `content.slice(0, ceil(len*textP))` в UTF-16-единицах (`AnnotationOverlay.tsx:188-191`, `annotationRenderer.ts:680-683`). На выходе символы стираются с конца. Перенос строк пересчитывается для обрезанной строки на каждом кадре, поэтому слово перескакивает на следующую строку, пока печатается. В v2 текст раскладывается целиком один раз, а открываются графемы.

## 4. Ключевые кадры

### 4.1. Данные

`AnnotationPositionKeyframe` (`types.ts:874-900`) содержит:
- `id`;
- `timeMs` — **абсолютное** время таймлайна, округлённое до мс;
- `position`, `size?`;
- `properties?` — полный снимок `AnnotationKeyframeProperties`.

Ключ без `properties` хранит только положение и размер.

В ключ попадают: `position.x/y`, `size.width/height`, `type`, `content`, все поля `style` (color, backgroundColor, fontSize, fontFamily, fontWeight, fontStyle, textDecoration, textAlign, borderRadius), все поля `figureData` (kind, arrowDirection, color, strokeWidth, opacity, fillEnabled, fillColor, fillGradient.*, outlineEnabled, gradient.*), `drawingData` целиком, `stages`, `blurIntensity` и `blurColor` (`annotationKeyframes.ts:77-92`). Не ключуются `start/end`, `trackIndex` и `zIndex`.

### 4.2. Интерполяция

Положение и размер (`annotationKeyframes.ts:14-47`):

```
F = все ключи по времени
if F пуст: return (a.position, a.size)                  // база
if t <= F[0].t: return F[0]          // держим первый ключ
if t >= F[last].t: return F[last]
r = первый i с F[i].t >= t; l = r - 1
e = smooth((t - F[l].t) / max(1, F[r].t - F[l].t))
x,y,w,h = L + (R - L)*e              // у ключа без size берётся a.size
```

Скорость в каждом ключе нулевая: каждый отрезок разгоняется и тормозит заново. Тест: ключи 1000→3000 мс, x 0→100, при t=1500 x=15.625 (`annotationKeyframes.test.ts:21-30`).

Остальные параметры (`annotationKeyframes.ts:110-165`):

```
P = ключи с properties по времени; base = параметры аннотации
expand(p) = {...base, ...p, style: {...base.style, ...p.style}}
if P пуст: base
if t <= P[0].t:
   if P[0].t <= start || t == P[0].t: return expand(P[0])
   return mix(base, expand(P[0]), smooth(clamp01((t - start) / (P[0].t - start))))
if t >= P[last].t: return expand(P[last])
mix(expand(P[l]), expand(P[r]), smooth(...)) как выше

mix(L, R, e):
  if e >= 1: return R                       // только когда t ровно на правом ключе
  number+number: L + (R - L)*e              // без округления: fontSize 30.7 возможен
  string+string: обе вида ^#[0-9a-f]{6}$ ? по каналам sRGB round(L*(1-e) + R*e) : L
  array+array одной длины: поэлементно mix
  object+object: по ключам L (ключ, которого нет в L, до e=1 теряется)
  иначе: L                                  // bool, enum, текст, "transparent" — ступенька в правом ключе
```

Тест: цвет #000000→#ffffff даёт #808080 на половине, текст меняется скачком (`annotationKeyframes.test.ts:107-133`).

**Не переносить:**
- До первого ключа положение и размер держат первый ключ, а остальные параметры плавно идут от базы с `startMs`. Правило нужно выбрать одно для всех параметров.
- Если ключи есть, база положения не видна вообще, хотя в ручном режиме правка между ключами пишется именно в базу. Пользователь двигает аннотацию, а она не двигается.
- Одинаковые по длине массивы штрихов и точек морфятся. Ключуются `type` и `stages`, и это странно.
- Ключи хранят абсолютное время и не сдвигаются, когда аннотацию двигают по таймлайну, дублируют или сдвигают рябью от клипов (`useAnnotationRegionCommands.ts:73-95, 178-201`, `clipSequence.ts:93-115`). Совет для v2: хранить время ключа относительно `startMs`.
- При загрузке время ключа зажимается в `[startMs, endMs]` (`projectPersistence.ts:645`).
- Клавиша I может поставить ключ вне аннотации, потому что время зажимается только в `[0, totalMs]`.

### 4.3. Режимы и команды

- Режим — `"auto"` или `"off"` (ручной); третий `"manual"` в типе есть, но не используется. По умолчанию `"off"`, режим не сохраняется (`layout/EditorShell.tsx:65, 146`). Кнопка-ромб переключает авторежим, глазик показывает или скрывает маркеры (`showKeyframes`, по умолчанию `true`, `EditorShell.tsx:66`).
- **Куда пишется правка** (`layout/EditorPreviewPanel.tsx:139-147`, `EditorShell.tsx:166-170`). Если включён `auto` или у аннотации есть ключ в пределах 1 мс от курсора времени, правка идёт в ключ. Иначе правится база.
- **Запись положения** (`annotationKeyframes.ts:172-201`):
  1. `time = clamp(round(t), start, end)`.
  2. Если значение совпадает с вычисленным, ничего не делать.
  3. Если ключей ещё нет и `time > start`, сначала поставить ключ в `startMs` с базовым положением и размером: движение начнётся от исходного места.
  4. Поставить или обновить ключ в `time`. Существующим считается ключ в пределах 1 мс.
- **Запись остальных параметров** (`annotationKeyframes.ts:203-221`):
  1. `time` зажимается так же.
  2. Если ни одно значение не изменилось (сравнение JSON), ничего не делать.
  3. Иначе `properties = deep_clone({...resolved(time), ...change})`, а ключ в `time` получает положение и размер, вычисленные на это время.
- **I** — физическая клавиша `KeyI` без модификаторов, работает в любой раскладке (`timeline/hooks/useTimelineKeyboardShortcuts.ts:82`). Ставит ключ выбранной аннотации в любом режиме (`timeline/hooks/useTimelineSelection.ts:81-99`):
  - `time = round(clamp(t, 0, totalMs))`;
  - если ключ в пределах 1 мс уже есть, он просто выбирается;
  - иначе создаётся ключ с вычисленными на `time` положением, размером и полным снимком параметров, и он сразу выбирается.
- **Delete/Backspace** удаляет выбранный ключ раньше, чем аннотацию (`useTimelineKeyboardShortcuts.ts:90-115`).
- **Перетаскивание маркера** меняет время ключа в пределах `[0, totalMs]` (`useTimelineSelection.ts:134-148`).
- **Ctrl+C** при выбранном ключе копирует его глубокой копией вместе с id аннотации в буфер в памяти.
- **Ctrl+V** имеет приоритет над вставкой регионов, если в буфере есть ключ (`useTimelineSelection.ts:114-133`):
  - цель — выбранная аннотация, а если её нет, исходная;
  - `time = round(clamp(t, 0, totalMs))`;
  - ключи цели в пределах 1 мс удаляются;
  - вставляется копия с новым id, и она выбирается.

  Ключ можно вставить в аннотацию другого типа. Вместе с ним переедет `type`. **Не переносить:** вставлять можно только в аннотацию того же вида.
- **Подсказка над маркером** (`keyframeChanges.ts:4-76`). Ключи перебираются по времени, и каждый сравнивается с предыдущим состоянием (для первого — с базой). Каждое изменение выводится строкой «Название: было → стало»:
  - целые числа как есть, дробные `toFixed(2)`;
  - bool — On/Off;
  - строки длиннее 32 символов обрезаются до 29 и «…»;
  - массивы через «, », объекты как «Changed»;
  - если изменений нет — «No parameter changes».

  В v2 тексты на русском.

## 5. Текст

- **Шрифты v1 — системные, файлов нет** (`AnnotationSettingsPanel.tsx:71-83`; подписи в `config/locales/ru/editor.json:120-129`):

  | Пресет | font-family |
  |---|---|
  | Классический | `system-ui, -apple-system, sans-serif` |
  | Базовый | `Georgia, serif` |
  | Акцентный | `Impact, Arial Black, sans-serif` |
  | Моноширинный | `Courier New, monospace` |
  | Декоративный | `Brush Script MT, cursive` |
  | Простой | `Arial, sans-serif` |
  | Современный | `Verdana, sans-serif` |
  | Минималистичный | `Trebuchet MS, sans-serif` |

  Шрифт по умолчанию, SF Pro Display, не входит в список; на Windows его нет. Свои шрифты в v1 — URL Google Fonts в localStorage (`lib/customFonts.ts:1-206`). В v2 их заменяют `.ttf`/`.otf` в `assets/` проекта (вопрос 7).
- **Размер** выбирается из списка `[12,14,16,18,20,24,28,32,36,40,48,56,64,72,80,96,128]` ref-px (`AnnotationSettingsPanel.tsx:85`). Ключи дают дробные промежуточные значения.
- **Масштаб с разрешением выхода:** `fs_px = fontSize * k = fontSize * Rw/1920 * cam.s`. Например, в 4K (Rw=3840) 32 становится 64 px, при зуме 2× — ещё вдвое больше.
- **Стиль:** жирный — `bold`, курсив — `italic`, подчёркивание рисуется вручную. Выравнивание left/center/right. Цвет текста; фон — цвет или `"transparent"`.
- **Раскладка** (эталон — экспорт, `lib/exporter/annotationRenderer.ts:461-578`):

```
fs = fontSize*k; pad = 8*k; clip(X,Y,W,H)              // текст режется по боксу
font = "{italic|normal} {bold|normal} {fs}px {family}"; baseline = middle
anchor = left: X+pad | right: X+W-pad | center: X+W/2  (без pad)
avail = W - 2*pad
lines = []
for raw in text.split("\n"):
  if raw == "": lines.push(""); continue
  cur = ""
  for tok in raw.split(/(\s+)/):                        // слова и группы пробелов по очереди
    if cur != "" && measure(cur + tok) > avail: lines.push(cur); cur = tok.trimStart()
    else: cur = cur + tok
  if cur != "": lines.push(cur)
lh = 1.4*fs; y0 = Y + H/2 - (n-1)*lh/2                  // блок по центру бокса по вертикали
for i, line: y = y0 + i*lh
  if bg != transparent:                                 // плашка на каждую строку
     bw = measure(line) + 0.4*fs; bh = 1.6*fs           // отступы 0.2fs по бокам и 0.1fs сверху/снизу; 1.4fs — высота содержимого
     bx = left: anchor-0.2fs | center: anchor-bw/2 | right: anchor-bw
     roundRect(bx, y-bh/2, bw, bh, r = 4*k)
  fillText(line, anchor, y)
  if underline: line from x_start to x_start+measure(line) at y+0.15*fs, width max(1, fs/16), цвет текста
```

**Радиус плашки в v1 жёстко 4 ref-px**, поле `style.borderRadius` (по умолчанию 8) для текста не используется, а настройки в UI нет. В v2 появляется настройка радиуса, по умолчанию 4 (так выглядит v1).

**Не переносить:**
- Слово длиннее строки не переносится и обрезается боксом. В превью CSS `word-break: break-word` его переносит.
- Хвостовые пробелы строки остаются, поэтому центр и правый край строки и ширина плашки получаются неточными.
- Пустая строка с фоном рисует пустую плашку шириной 0.4fs.

Чем превью отличается от экспорта (`AnnotationOverlay.tsx:154-194`):
- отступ 8·sizeScale со всех сторон;
- плашка строится как фон inline-span: высота — content-area шрифта плюс 0.2fs, а не 1.6fs.

Changelog 0.11 называет переносы совпадающими (`config/Changelog.md:120`), но они совпадают только приблизительно.

## 6. Фигуры

### 6.1. Общие параметры

- **Прозрачность** `opacity` 0..1 с шагом 0.01 (`AnnotationSettingsPanel.tsx:811-812`). В экспорте `globalAlpha *= opacity` применяется к каждой операции отдельно, поэтому заливка и обводка перекрываются двойным смешением. В превью прозрачность групповая. В v2 прозрачность применяется к слою целиком.
- **Толщина** `strokeWidth` 1..6 с шагом 1, по умолчанию 4 (`AnnotationSettingsPanel.tsx:907-923`).
  - Для прямоугольника, эллипса, круга, линии и подсветки это ref-px: `lw = max(1, strokeWidth*k)` (`annotationRenderer.ts:288`). От размера бокса толщина не зависит (`config/Changelog.md:122`).
  - **У стрелки это единицы её viewBox**, и толщина растёт вместе с боксом (6.3).
  - **Не переносить:** превью рисует обводку фигур и рисунков в CSS-пикселях (`vector-effect: non-scaling-stroke`, `AnnotationOverlay.tsx:263, 546`) без множителя sizeScale. Поэтому в превью линии примерно вдвое толще, чем в экспорте.
- **Заливка** есть только у rectangle, ellipse, circle и highlight (`AnnotationSettingsPanel.tsx:137`). Режимы: цвет `fillColor` (по умолчанию равен `color`) или анимированный градиент `fillGradient`. У highlight без `fillGradient` берётся `gradient`.
- **Обводка** включается и выключается только у фигур с заливкой; у стрелки и линии она всегда есть. Параметры: цвет `color`, анимированный градиент обводки `gradient`.
- **Градиент v1 всегда анимированный и горизонтальный в осях бокса** (`types.ts:983-1008`):

```
fn stops(g, t, fallback):                   // t — абсолютное время таймлайна
  if !g.enabled: return [fallback]
  C = g.colors.filter(^#[0-9a-f]{6}$i);  if len(C) < 2: return [fallback]
  D = max(250, g.cycleDurationMs || 2400);  phase = ((t % D) + D) % D / D
  for s in 0..=8:                           // 9 стопов на offset s/8
    pos = ((phase + s/8) % 1) * len(C);  i = floor(pos);  b = pos - i
    stop[s] = per-channel round(C[i]*(1-b) + C[(i+1) % len(C)]*b)   // sRGB, по кругу к первому
```

  - Линейный градиент идёт от левого края бокса к правому, `(X,Y)` → `(X+W,Y)` (`annotationRenderer.ts:266, 275`). У стрелки — по её квадрату 100·s (`annotationRenderer.ts:193`).
  - Стоп 0 и стоп 8 совпадают, поэтому цикл бесшовный. Узор сдвигается **влево** на ширину бокса за `D` мс.
  - Цветов 2–4; новый цвет копирует последний (`AnnotationSettingsPanel.tsx:825-829`). В UI нет ни скорости (всегда 2400 мс), ни направления.
  - Тест: цвета #FF0000 и #0000FF, D=300, t=75 → стоп 0 = #800080 (`annotationModel.test.ts:115-132`).
- **Свечение** (glow 0..40, по умолчанию 14) в v1 **есть только при включённом градиенте** (`annotationRenderer.ts:241-244, 282-287`):

```
glow = max(outline && gradient.enabled ? gradient.glow : 0, fill && fillGradient.enabled ? fillGradient.glow : 0)
if glow > 0: shadowColor = (fill && fillGradient.enabled) ? fillStops[4] : strokeStops[4]   // средний стоп
             shadowBlur = 1.5*glow*k   (canvas shadowBlur = 2σ → σ = 0.75*glow*k), offset 0
```

  Превью рисует две CSS-тени: `drop-shadow(0 0 max(2, 0.6*glow*sizeScale)px c)` и `drop-shadow(0 0 max(4, 1.35*glow*sizeScale)px c)` (`AnnotationOverlay.tsx:239-248`). В превью радиус CSS тоже равен 2σ.

  **Не переносить:** две разные формулы. Берётся одна формула экспорта.

### 6.2. Геометрия по видам

Экспорт: `annotationRenderer.ts:288-326`; превью — viewBox 100×100, `AnnotationOverlay.tsx:259-293`.

```
lw = max(1, strokeWidth*k); inset = lw/2; порядок: сначала заливка, потом обводка; cap и join round
highlight: fillRect(X,Y,W,H) без отступа; обводка strokeRect(X+inset, Y+inset, W-2inset, H-2inset)
rectangle: заливка и обводка по rect(X+inset, Y+inset, W-2inset, H-2inset)
ellipse:   центр бокса, rx = max(0, W/2-inset), ry = max(0, H/2-inset)
circle:    центр бокса, r = max(0, min(W,H)/2 - inset)  // пропорции держит рендер, бокс может быть неквадратным
line:      (X+inset, Y+H-inset) → (X+W-inset, Y+inset)  // всегда «/» снизу-слева вверх-вправо, без заливки
```

Отличия превью: отступ 3 % бокса (`rect x=3 w=94`, `ellipse r=47`, `line 3,97→97,3`, `circle r=47` с `meet`), обводка по центру контура. У прямоугольника в превью острые углы (miter по умолчанию в SVG), в экспорте скруглённые (`lineJoin round`). См. вопрос 9.

### 6.3. Стрелка v1: 8 направлений, геометрия для стрелки по двум точкам

Пути в viewBox 100×100 (`ArrowSvgs.tsx:24-171`, `annotationRenderer.ts:121-130`):

```
right:      M20 50 L80 50 | M80 50 L65 35 | M80 50 L65 65      left/up/down — поворот на 90°/180°
up-right:   M25 75 L75 25 | M75 25 L60 30 | M75 25 L70 40      и аналогично 3 других диагонали
```

Размещение (`annotationRenderer.ts:156-220`):

```
pad = 8*k; aw = max(0, W-2pad); ah = max(0, H-2pad); s = min(aw, ah)/100     // вписывание «meet»
origin = (X + pad + (aw - 100s)/2, Y + pad + (ah - 100s)/2)
point_px = origin + point_viewbox * s;  lineWidth = strokeWidth * s;  cap = join = round
тень без glow: rgba(0,0,0,0.3), shadowBlur 8*s, offsetY 4*s
с glow: средний стоп градиента, shadowBlur 1.5*glow*k, offset 0
```

В превью тень — `feDropShadow dy=2 stdDeviation=4 opacity 0.3` в единицах viewBox (`ArrowSvgs.tsx:20`), то есть сдвиг вдвое меньше.

Пропорции стрелки:
- **Прямая стрелка:** древко 60 единиц, усы по 15√2 ≈ 21.21 под ±45° к древку. Ус равен 0.354 древка, полуширина головы 0.25 древка, толщина `strokeWidth/60` древка.
- **Диагональная стрелка:** древко 50√2 ≈ 70.71, усы √250 ≈ 15.81 под ±26.57°. Ус равен 0.224 древка, полуширина головы 0.1 древка. Головы у неё уже — это артефакт рисунка, переносить не нужно.
- **Стрелка по умолчанию** (30 % × 20 % от 1920×1080, бокс 576×216): s = 2.0, древко 120 px, толщина 8 px, усы 42.4 px, тень blur 16 и сдвиг 8.

Стрелка v1 не растягивается по боксу. Она вписана в квадрат `min(W,H)`, поэтому в широком боксе остаётся короткой.

Чтобы стрелка v2 от P0 до P1 (`L = |P1-P0|`) выглядела точно как прямая стрелка v1:

```
s = L/60; T = strokeWidth*s; усы от P1 длиной 15√2*s под ±45° к направлению (P0-P1)
```

Но тогда толщина растёт с длиной, а в остальных фигурах и по SCOPE толщина постоянна (вопрос 2).

## 7. Изображение

- Форматы JPEG, PNG, GIF и WebP, проверка по MIME (`AnnotationSettingsPanel.tsx:171-205`). В v1 картинка хранится data-URL прямо в проекте; в v2 файл копируется в `assets/`.
- Рисуется по правилу contain: вписывается в бокс с сохранением пропорций и центрируется (`annotationRenderer.ts:599-615`). Бокс под размеры картинки не подгоняется. Своей прозрачности у картинки нет.
- **Не переносить:** анимированный GIF в превью проигрывается, а в экспорте застывает на первом кадре (вопрос 11).

## 8. Рисование

**Данные** (`types.ts:586-607`):

```
strokes: [[{x,y}]]   // x,y в % бокса 0..100, при вводе и загрузке зажимаются в 0..100
color; strokeWidth (1..24, ref-px, по умолчанию 4); eraserSize (4..48, по умолчанию 12); gradient
```

`points` — устаревший сплющенный список, в v2 не нужен.

**Ввод** (`AnnotationOverlay.tsx:331-512`):
- Работает, только когда аннотация выбрана. Перетаскивание бокса у рисунка выключено (`AnnotationOverlay.tsx:741`); бокс двигает **ПКМ с перетаскиванием** (`AnnotationOverlay.tsx:444-486`). Ресайз бокса растягивает штрихи, толщина остаётся прежней.
- **ЛКМ down** начинает новый штрих `[p]`. Каждый pointermove добавляет точку. **Сглаживания и прореживания нет:** штрих — сырая ломаная с круглыми join и cap.
- **Shift при движении** заменяет штрих на `[первая точка, текущая]`, получается прямая от начала штриха (`AnnotationOverlay.tsx:396-398`). Если отпустить Shift, точки снова добавляются к этим двум.
- **Ластик** включается только кнопкой инструмента. **Shift+ЛКМ как ластик в коде v1 не реализован**, хотя `config/Changelog.md:93` его обещает (вопрос 1). Алгоритм (`types.ts:1011-1036`, `AnnotationOverlay.tsx:368-389`):

```
r% = (eraserSize/2) / max(1, min(boxW_screen_px, boxH_screen_px)) * 100;  r% = max(0.1, r%)
для каждого штриха: удалить точки с hypot(p - cursor) <= r% (в % бокса), штрих рвётся на куски
```

  Отрезок между двумя дальними точками ластик не режет. Прямая из Shift стирается только у концов.
- Кнопка «Очистить» делает `strokes = []`.
- Курсор кисти — кружок диаметром strokeWidth или eraserSize в CSS-пикселях.

**Рендер** (`annotationRenderer.ts:330-379`):
- `lw = max(1, strokeWidth*k)`, точка переводится так: `(X + x/100*W, Y + y/100*H)`.
- Штрих из одной точки рисуется круглой точкой (lineTo со сдвигом +0.01 px).
- Градиент как в 6.1. Свечение только при ≥2 цветах: `shadowColor = stop[0]`, `shadowBlur = glow*k` (σ = 0.5·glow·k). Цвет здесь первый стоп, а у фигур средний.

**Draw-in** (`types.ts:805-862`):

```
len(stroke) = 0 если пуст; 1 если одна точка; иначе max(1, Σ hypot сегментов)   // в % бокса
remaining = Σ len * clamp01(p)
для штрихов по порядку: если remaining >= len → весь, remaining -= len
  иначе: первая точка + целые сегменты + частичный сегмент с ratio = remaining/seg; remaining = 0
```

Скорость прорисовки по длине пути постоянна, но длина считается в % бокса. **Не переносить:** в неквадратном боксе экранная скорость плавает, считать надо в пикселях.

**Не переносить:**
- Слайдеры толщины и цвета кисти теряют `gradient`, `tool` и `eraserSize` (`AnnotationSettingsPanel.tsx:1171-1178, 1207-1214`).
- Радиус ластика считается изотропно в % бокса, поэтому в неквадратном боксе пятно стирания эллиптическое.

## 9. Размытие области

- **Сила** `blurIntensity` 1..100, по умолчанию 20 — это σ гаусса в ref-px: `σ = blurIntensity * k` (`AnnotationSettingsPanel.tsx:1027-1039`, `annotationRenderer.ts:732-733`). В превью — CSS `backdrop-filter: blur(σ px)` (`AnnotationOverlay.tsx:313-329`).
- **Углы:** скругление `style.borderRadius * k`, по умолчанию 8 ref-px. В UI настройки нет; по правилам SCOPE такое скрытое поле запрещено (вопрос 3).
- **Что размывается:** всё, что уже нарисовано под аннотацией: видео, курсор и аннотации нижних слоёв (`annotationRenderer.ts:743-758`). Экспорт:

```
pad = ceil(2σ); src = clamp_to_canvas(X-pad, Y-pad, W+2pad, H+2pad)
clip(roundRect(X,Y,W,H,radius)); drawImage(blur(copy(src), σ), src.x, src.y)
if blurColor && blurColor != "transparent": fillRect(X,Y,W,H, blurColor)   // в том же clip
```

- **«Тонировка» в v1 — непрозрачная заливка.** В UI она подписана «Сплошной цвет (цензура)», альфа-канала у пикера нет (`components/ui/color-picker.tsx:66-69`). Цвет #RRGGBB полностью закрывает размытие. По умолчанию цвета нет (вопрос 3).

**Не переносить:**
- Буфер обрезается краем кадра, а canvas-blur считает пиксели за краем прозрачными. У края кадра внутрь пролезает неразмытая картинка; в v2 нужна выборка clamp-to-edge.
- Во время pop и slide размытый фрагмент берётся из нетрансформированного места, а рисуется со сдвигом и масштабом. Размытое содержимое съезжает.

## 10. Граничные случаи

| Случай | Поведение v1 | Для v2 |
|---|---|---|
| Зум камеры | Аннотации живут в пространстве сцены и **едут и масштабируются вместе с камерой** в превью (CSS-матрица камеры на слое, `VideoPlayback.tsx:2893-2900`) и в экспорте (`sceneTransform`, `annotationRenderer.ts:651-661`; спрайты в `cameraContainer`, `modernFrameRenderer.ts:561`). Шрифт, толщина, свечение, σ blur и сдвиг slide умножаются на `cam.s`. Части аннотации, ушедшие за кадр при зуме, обрезаются. | Так же: аннотация рисуется до камеры, в координатах кадра. |
| Кроп | Координаты в % от видимого прямоугольника после кропа (`maskRect`). При смене кропа аннотация остаётся на том же месте кадра, а не на тех же пикселях исходника. | Доли кадра проекта; клип с другим аспектом — вопрос 5. |
| Аннотация частично за кадром | В превью бокс нельзя вытащить за сцену (`bounds="parent"`, `AnnotationOverlay.tsx:727`). При загрузке позиция не зажимается. Экспорт обрезает краем кадра. Текст режется по своему боксу, стрелка, свечение и тень могут выходить за бокс. С blur у края — баг из раздела 9. | Разрешить, обрезать по кадру. |
| Нулевая длительность | Таймлайн не даёт меньше 100 мс, загрузка — меньше 1 мс. Все деления защищены `max(1, …)`. | Минимум 100 мс в командах. |
| Стадии длиннее аннотации | Вход в приоритете (раздел 3). | Зажимать при любом изменении длины. |
| Перекрытие по времени | Разрешено на любой дорожке; порядок по 2.3. | Так же. |
| Ровно `t = startMs` и `t = endMs` | Аннотация видна, обе границы включены. На входе p=0, на выходе p=0: при fade/pop/slide `alpha = 0`. Две аннотации встык на t=граница видны обе. | Сделать конец исключающим или оставить — решить один раз для всех дорожек. |
| Конец видео | Новая аннотация не выходит за `totalMs`. На последнем кадре действует правило границы. | — |
| Ключ вне `[start, end]` | Клавиша I и вставка ставят ключ вне аннотации, при загрузке он зажимается. | Зажимать сразу. |
| Анимированный градиент | Фаза идёт от абсолютного времени таймлайна. **Не переносить:** спрайтовый путь экспорта рендерит текстуру один раз на `startMs`, и градиент застывает. Если у кадра нет стадий, ключей и blur, применяется этот путь (`modernFrameRenderer.ts:1457-1470, 1589-1596`). | Один рендер, фаза от времени кадра. |
| Смена пути рендера | Как только становится активной аннотация со стадиями, ключами или blur, **все** аннотации кадра переходят на Canvas2D. Вид может прыгнуть посреди ролика (`modernFrameRenderer.ts:3038-3065`). | Один рендер. |

## 11. Открытые вопросы владельцу

1. **Shift в рисовании.** SCOPE: «ластик (Shift+ЛКМ), прямая линия (Shift)». В v1 Shift во время штриха даёт прямую, ластик включается только кнопкой. Какая комбинация даёт ластик, а какая — прямую?
2. **Толщина стрелки.** В v1 толщина и голова стрелки растут вместе с боксом (`T = strokeWidth*L/60`, ус `0.354·L`). Для v2 толщина постоянная в ref-px? Предложение: `T = 2*strokeWidth` ref-px (как у стрелки по умолчанию в v1), ус `min(0.354·L, 5.3·T)` под ±45°.
3. **Blur.** Тонировка в v1 — непрозрачная «цензура». В v2 это полупрозрачный оттенок? С какой альфой по умолчанию? Радиус углов (сейчас скрыто 8 ref-px) вынести в UI или зашить?
4. **Названия slide.** `up/down` = направление движения, `left/right` = сторона появления. Какой смысл принять для всех четырёх?
5. **Пространство координат.** Кадр проекта или прямоугольник конкретного клипа, если у клипа другой аспект с чёрными полями? Предложение: кадр проекта.
6. **Время.** ARCHITECTURE привязывает аннотации ко времени исходника, а в v1 длительности стадий, ключи и цикл градиента идут по времени выхода. Что делать при ускорении участка 4× — fade 300 мс укорачивается до 75 мс или нет?
