# DevCast v2: архитектура

Технологии перепроверены 2026-10-27 по crates.io и GitHub. Версии фиксируются в `Cargo.lock` и обновляются только отдельной задачей.

## Стек

| Что | Чем | Почему, и на что смотреть |

| Интерфейс | egui/eframe 0.37 на wgpu 30 | UI — функция от состояния. Текстуры рендера показываются без копирования (`egui_wgpu::Callback` / `register_native_texture`, формат `Rgba8Unorm`). | Корзина | trash 5 | Библиотека записей отправляет проекты в корзину Windows и возвращает последнюю пачку (`os_limited::restore_all`); решение владельца 2026-11-02. |
| Логи и падения | tracing + tracing-appender (держать `WorkerGuard`), panic hook; crash-handler + minidumper для падений в нативном коде | |

**Лицензия.** v2 выходит под AGPL-3.0, как и v1: алгоритмы переносятся из v1. Код Cap (AGPL/MIT) можно брать как образец, при копировании сохраняя уведомления. Крейт `dssim` не используем.

## Главные решения

1. **Проект — это папка `name.devcast/`.**
   ```
   project.json      сохранённое состояние (Ctrl+S): маленький файл, читается глазами
   session.json      рабочее состояние: автосохранение и восстановление после вылета
   history.jsonl     журнал команд: undo/redo, общий для GUI и CLI
   media/            записи (сегменты → mp4), импортированные видео, звук, cursor.bin, keys.bin
   assets/           шрифты, картинки, курсоры, которые использует проект
   cache/            превью, волна, транскрипт, индексы ключевых кадров; можно удалить
   ```
   Если проект не открыт в редакторе, CLI применяет команду и сразу сохраняет. Если открыт, команда идёт в рабочее состояние редактора, и у названия появляется точка несохранённых изменений.
2. **Всё привязано ко времени исходника.** У каждого клипа своё source time. Нарезка, порядок клипов и скорость — это только карта времени source ↔ output. Если вырезать кусок, зумы, аннотации, субтитры и события курсора сдвигать не нужно. Эффекты на дорожках привязаны к записи (файл `Media.path` + время в нём), а не к клипу. Разрезание (как Blade в DaVinci) и перестановка клипов их не трогают, а настройки клипа (кроп, вырезы, скорость) копируются в обе половины. Исключения идут по времени выхода: дополнительные аудиодорожки и длительности анимаций (вход/выход аннотаций, печать облачка, эффекты кликов, анимации субтитров) — на ускоренном участке они идут с нормальной скоростью.
3. **Всё — команды.** Любое изменение — это `Command` из реестра: `apply(&mut Project) -> Result<Diff>`, и команда хранит обратную. Кнопка, хоткей, CLI и пакетный план идут одним путём. Другого способа изменить проект нет. Горячие клавиши тоже привязаны к командам, поэтому переназначить можно любую.
4. **Рендер — чистая функция в два шага.** `evaluate(project, t) -> Scene` работает на CPU, детерминирована и тестируется JSON-снимками. `draw(scene) -> кадр` работает на GPU. Превью, экспорт и `devcast frame` используют одно и то же: `dc_ops::Evaluator` вызывает `evaluate` эффектов в постоянном порядке (решение 015).
5. **Эффект — вертикальный срез, один крейт.** В нём модель, команды, `evaluate`, `draw`, панель UI, справка для CLI и тесты. Новая фича — это новый крейт и одна строка регистрации.
6. **Писатель всегда один.** Если проект открыт в редакторе, CLI работает через него по IPC (канал `devcast-app-<пользователь>`, `dc_ops::live`, решение 011): редактор кладёт рабочее состояние на диск, CLI выполняет команду тем же кодом и отправляет события истории; редактор берёт их одним шагом своей истории, если его ревизия не сменилась. Иначе CLI правит файлы под lock-файлом.
7. **Настройки по умолчанию** лежат в одном файле приложения. Новый проект копирует их к себе. «Сбросить» у группы возвращает значения по умолчанию, «Сбросить к заводским» — встроенные.
8. **Платформенный код** есть только в `capture/<os>`, `encode` (аппаратные кодеки), `update` и в мелких адаптерах `app` (трей, исключение окна из захвата).

**Правила зависимостей** (проверяет `cargo xtask verify`):
- `core` ни от кого не зависит.
- `fx/*` зависят только от `core`, API `render`, `ui-kit` и `egui`. Друг от друга они не зависят. Исключение: виды аннотаций зависят от `fx/annotations`.
- `app` и `cli` — верхний уровень, от них никто не зависит.
- `app` не зависит от `transcribe` ни напрямую, ни через другие крейты (решение 018): окно программы не линкует whisper и Vulkan.

## Панель эффекта

Панель инспектора живёт в крейте своего эффекта (решение 5, решение владельца 2026-11-02); образец — `fx/keys/src/panel.rs`; все панели перенесены в задаче 7.35.

- **Шов.** Эффект экспортирует модуль `panel`: `pub const ID` (первая часть ключа групп, обычно `Effect::ID`) и `pub fn ui(ui, cx: &mut dc_ui_kit::panel::Cx, факты…)`. Рисует только через `dc_ui_kit` (egui — его реэкспорт `dc_ui_kit::egui`, строки — `dc_ui_kit::strings`).
- **Что даёт редактор** — `dc_ui_kit::panel::Cx`: проект, проект умолчаний (`defaults_of::<E>()` для «Сбросить»), указатель, «Авто-ключи», шрифты пикеров, память групп `Groups` (открыта/свёрнута, `settings.json`). То, что знает только редактор (телеметрия записей, распознавание, дорожки звука), панель получает отдельным аргументом-фактами своего типа, посчитанным кодом эффекта (`dc_fx_keys::panel::Shortcuts::of`); редактор только хранит его. Состояние, которого нет у эффекта, редактор переводит в типы фактов эффекта сам (`dc_fx_captions::panel::Recognition`: фаза распознавания — общий тип редактора и панели, модель, язык, дорожки). Выбор панели, который не правка проекта, а настройка программы (язык и дорожки субтитров), панель пишет в факты (`&mut`), редактор забирает его после раскладки.
- **Что отдаёт панель** — `Cx::edits`: списки `dc_core::Step` (команда реестра по имени и аргументы, как в `devcast`), каждый — один шаг undo; `Cx::adds` — такие же списки, добавленное ими редактор выбирает (`Action::Paste`). Сокращение, которое строит dc-ops по файлам проекта (`zoom add --at clicks`, «Подобрать зумы»), — тоже `Step`: редактор применяет его как `devcast` (`Document::apply_resolved`). `Step` лежит в dc-core, потому что эффекты ниже dc-ops; dc-ops строит и применяет его как раньше (`dc_ops::Step` — реэкспорт). Просьбы не о проекте — `Cx::requests`, перечисление `dc_ui_kit::panel::Request`, варианты названы по тому, что делает редактор: `Pick(id)` (выбрать объект по id, как его пишет `devcast`, панель остаётся открытой; редактор находит его `Item::parse`), `Seek(время)` (переход указателя), `AddFont(Step)` (диалог файла шрифта, затем шаг с его семейством — ряд `Cx::font`), `Picture { id, at }` (диалог картинки, копия в проект и `image set` аннотации — «Заменить…»; `image set` не команда реестра, поэтому не `Step`), `Recognize`/`StopRecognizing` (распознавание). Редактор превращает их в свои `Action` после раскладки (`inspector::action`). Вариант добавляет тот, кому он нужен; заранее — нет.
- **Набор** `dc_ui_kit::panel`: `header`, `Cx::group` (`Group` с «Сбросить» — `reset(op, сейчас, умолчания)`; `Cx::group_with` — ещё кнопка в шапке группы), `rows` (строки: черновик до отпускания, текст до Enter, `rows::flush`), `padded`, `args`; ряды окна настроек — `dc_ui_kit::settings_rows`.
- **Регистрация** — одна строка в `crates/app/src/editor/inspector/mod.rs` (`tab` или `object.rs` для объекта): id и функция, которая передаёт `cx.base` и факты.
- **Аннотации.** Общая панель — `dc_fx_annotations::panel` (строка ключа, «Вход и выход», «Тонкая настройка»; `Edit` — куда идёт правка, `target` — ключ у указателя или новый с «Авто-ключами», его зовёт и правка на превью); поля вида — трейт `panel::Section`, его реализует крейт вида для своего типа полей (`impl Section for TextBody` в `fx/text/src/panel.rs`). `dc-fx-annotations` не знает своих видов, поэтому вид выбирает регистрация (`object.rs`: `panel::kind` → `panel::ui::<TextBody>`); факты — `panel::Region` (место на выходе, ключи на выходе, кадр после кропа). Ключ у указателя выбирать не нужно: панель только правит (`--at`) и двигает указатель (`Seek`).
- **Тесты.** Логика и ответы панели — kittest в крейте эффекта (`testing::harness()` фичи `kittest`, состояние — свой `Cx`); снимки инспектора целиком остаются в dc-app и при переносе не меняются побайтно.
- **Проверка** — шаг `seams` в `xtask verify` (`xtask/src/seams.rs`): код `crates/app/src` (не тесты и не комментарии) называет `dc_fx_*` только в файлах регистрации (`editor/lanes.rs`, `inspector/mod.rs`, `object.rs`, `captions.rs`, `editor/crop.rs`, `generation.rs` — распознавание, решение 018), а они реэкспортируют только модули швов эффекта (`lane`, `stage`, `panel`, `dialog`), не крейт целиком и не другие его части. Почему так: имя крейта эффекта видно в тексте без сборки, а список файлов короткий и явный; правило не зависит от названий типов и не ломается при их переименовании.

## Дорожка эффекта

Поведение эффекта на таймлайне живёт в его крейте, как панель (решение владельца 2026-11-02, задача 7.35). Редактор делает только общие жесты: выбор, перетаскивание группы и краёв, привязку, резиновую рамку, призрак добавления.

- **Шов** — `dc_ui_kit::lane`. Объект на дорожке — `lane::Item`: id, как его пишет `devcast` (`z3`; префикс вида и номер), без типов эффектов; эффект получает свой id `item.id::<ZoomKind>()`. Что показать — `lane::Region` (место на выходе, подпись, бледный, `Item`, ключи).
- **Команды жестов** — `lane::Lane`, таблица функций эффекта (`dc_fx_zoom::lane::LANE`): `moved` (новое место и дорожка, `lane::Moved`), `resized` (край, `lane::Resize`), `copied` (Ctrl+C/V: команда, которая добавит объект снова, без `--at`), `duplicated` («Дублировать» панели, с местом); `removed`, `key_added`, `key_moved`, `key_removed` общие, их команды — поля `rm` и `keys` таблицы. Всё — `dc_core::Step`, как в `devcast`; команду называет её тип (`OpName::of::<ZoomSet>()`, verify `op_names`), не строка; отказ команды отменяет весь жест.
- **Регистрация** — `crates/app/src/editor/lanes.rs`: список дорожек; редактор находит дорожку объекта по префиксу (`lanes::of`), id из `devcast` — `lanes::parse`. Модули швов эффектов (`dc_fx_*::lane`, `stage`) редактор видит только через реэкспорт там (`lanes::zoom`, `lanes::annotations`, …).
- **Превью** — набор `dc_ui_kit::stage` (`geom`: экран ↔ px холста, повёрнутый бокс; `snap`: привязка и направляющие; `paint`). Жест эффекта на превью — модуль `stage` эффекта (`dc_fx_zoom::stage::ui`): своё состояние жеста (его хранит редактор, пока кнопка нажата) и ответ `stage::Answer` — черновик для превью (`Document::draft`), в конце команды одного шага undo.

## Правила кода

- Файл — не больше 400 строк, функция — не больше 80.
- Вне тестов нет `unwrap` и `expect`, нет `unsafe` вне `capture`, `encode` и модуля `dc-app` `crash.rs` (crash-handler, решение владельца 2026-10-30). У каждого `unsafe` есть комментарий `SAFETY:`.
- Ошибки оформляются через `thiserror`, а текст ошибки объясняет, что делать.
- Тексты окон (GUI) лежат только в `dc-ui-kit`. Описания команд CLI, их ошибки и ответы остаются рядом с командой (решение владельца 2026-11-02).
- Типы схемы снабжаются doc-комментариями: из них собирается `devcast help`. Остальные комментарии — только то, чего не видно из кода (см. корневой CLAUDE.md).
- В каждом крейте есть `CLAUDE.md` до 40 строк: зачем он, инварианты, как тестировать, куда не лезть. Корневой `CLAUDE.md` — до 150 строк.
- Процесс работы над задачей, проверки и правило «без костылей» описаны в [PROCESS.md](PROCESS.md).

## CLI для нейронки-монтажёра

**Принципы:**
- По умолчанию вывод короткий, `--json` — по запросу.
- Id короткие: `z3`, `a12`, `c2` (клип), `w140` (слово).
- Есть фильтры по времени.
- У всех изменяющих команд есть `--dry-run`.
- Ответ на изменение — одна строка с diff.
- Ошибка подсказывает, как её исправить.
- Картинки возвращаются путём к PNG.
- Результат пишется в stdout, ошибки в stderr, коды выхода 0, 1 или 2.

```
devcast help [cmd] [--json]
devcast record --source <screen:1|window:<id>|area:x,y,w,h> [--fps 60] [--duration 10] [--audio on|off] [--mic имя] [-o x.devcast] | record stop|pause|resume|cancel
devcast ls sources                               # мониторы, окна, микрофоны для record
devcast ls projects                              # последние проекты редактора и проекты папки записей
devcast config show | config set recording.fps=30 captions.language=ru | config reset [ключ...]   # настройки программы
devcast hotkeys ls | hotkeys set start_stop Ctrl+Alt+R [--swap] | hotkeys set pause --clear | hotkeys reset save|--all
devcast models ls | models download fast|accurate

devcast info | save [--as имя [--open]] | discard | open | close [--save|--discard] | rename <имя>
devcast trash <проект.devcast...> [--restore]          # в корзину Windows и обратно
devcast app status|show|quit                     # запущенная программа DevCast
devcast image set a3 --file x.png | font add <файл> | font ls
```
